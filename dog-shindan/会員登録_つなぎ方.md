# ワンソナ 会員登録・ログイン つなぎ方（エンジニアの方へ）

## まとめ

- **ワンソナ専用**の会員登録・ログインです（開運予報など、ほかのサービスのログイン画面は使いません）。
- **画面（UI）はすべて `dog-shindan/index.html` に作ってあります。** 新しく画面を作る必要はありません。
- 本番（44wansona.com）では、サーバーにつながるまで会員の画面を**かくしています**。
  `window.W44Auth`（下の形）をつなぐと、そのまま表に出て動きます。
- **画面と流れは、本番のアドレスで見られます**：
  https://44wansona.com/?acct=demo
  （スマホの中だけで動く見本。メールは送らず、「（見本）メールのボタンを押したことにする」で先に進めます）

## 画面の一覧（`#s-acct` の中。`accView(名前)` で切りかえ）

| 名前 | 画面 | 入口 |
|---|---|---|
| `signup` | 無料の会員登録（メール・パスワード8文字以上・規約の同意〈必須〉・お知らせメール〈任意〉） | トップの「会員登録（無料）」・マイページ・会員だけの機能の案内 |
| `sent` | メールを送りました（もう一度送る／**メールアドレスをまちがえた（入れ直す）**／ログインする） | 登録したあと |
| `verify` | 確認できました | メールのボタン（`?acct=verify&code=…`） |
| `choose` | どちらの記録を使う？（このスマホ／アカウント） | 両方に記録があるときのログイン後 |
| `login` | ログイン | トップ・マイページ |
| `forgot` | パスワードを作り直す（メールを送る） | ログインの「パスワードを忘れた方」 |
| `newpass` | 新しいパスワード | メールのボタン（`?acct=reset&code=…`） |
| `chmail` | メールアドレスを変える | マイページ（ログイン中） |
| `chpw` | パスワードを変える | マイページ（ログイン中） |
| `delete` | 退会する | マイページ（ログイン中） |

マイページには「○○でログイン中」・お知らせメールの受け取り・ログアウトの欄もあります（`#acct-box`）。

## 新規登録の流れ

1. 登録の画面でメール・パスワードを入れて「登録する」→ `signUp`
2. 「メールを送りました」の画面（入れたメールアドレスを大きく表示）
   - メールが届かない → 「もう一度送る」→ `resendVerification`
   - **メールアドレスをまちがえた → 「入れ直す」→ `signOut` して登録の画面へもどる（まちがえたアドレスを入れたまま・選んだ状態）→ 正しいアドレスで、もう一度 `signUp`**
3. メールのボタン（`https://44wansona.com/?acct=verify&code=XXXX`）→ `verifyEmail(code)` → 確認できました → マイページ

### お願い（まちがえたアドレスの扱い）

- まちがえたアドレスで作られた**確認前のアカウント**は、確認のメールの期限（24時間）が切れたら消してください。
- **確認前のアカウントと同じアドレスで `signUp` が来たときは、`email-in-use` にせず、作り直してください**（同じ人が入れ直すことがあるため）。

## つなぐもの：`window.W44Auth`

`connected: true` を持つオブジェクトを、`index.html` より前に読みこまれる script で `window.W44Auth` に入れてください。
どの関数も Promise を返します。失敗のときは `Error` に `code`（下の表）を入れて reject してください。
見本の動き（`demoAuth`）が `index.html` の「会員登録・ログイン」のところにあり、同じ形で返しています。

| 関数 | 中身 | 返すもの |
|---|---|---|
| `currentUser()` | 開いたときにログインのままか。**確認メールのボタンを別の画面（メールのアプリの中など）で押したあとも、サーバーの最新の状態（verified:true）を返してください**（元の画面にもどったとき、これを呼び直して登録が終わったかを確かめます） | `{email, verified, newsletter}` または `null` |
| `signUp(email, password, {newsletter})` | 登録して確認のメールを送る（ログインした状態にする） | `{email, verified:false, newsletter}` |
| `resendVerification()` | 確認のメールをもう一度送る | `true` |
| `verifyEmail(code)` | メールのボタンの code で確認する | `true` |
| `signIn(email, password)` | ログイン | `{email, verified, newsletter}` |
| `signOut()` | ログアウト | — |
| `sendPasswordReset(email)` | パスワードを作り直すメールを送る（登録がなくても成功で返す） | `true` |
| `resetPassword(code, password)` | 新しいパスワードにする | `true` |
| `changeEmail(newEmail, password)` | 新しいアドレスへ確認のメール／前のアドレスへ知らせ | `true` |
| `changePassword(oldPw, newPw)` | パスワードを変える | `true` |
| `setNewsletter(bool)` | お知らせメールの受け取り | `true` |
| `deleteAccount(password)` | 退会（記録も消す） | `true` |
| `loadData()` | アカウントに保存した記録（JSON） | オブジェクト または `null` |
| `saveData(data)` | 記録を保存（約2.5秒ごと・画面を閉じるとき） | `true` |

### エラーの code（画面に出す文は `ACC_MSG`）

`invalid-email`・`email-in-use`・`weak-password`・`wrong-password`・`too-many-requests`・`network`・`expired-code`・`requires-login`
（ほかの code は「うまくいきませんでした。少し時間をおいて、もう一度試してね」になります）

## メール

送るメールのひな形は `dog-shindan/mail/`（`README.md` に件名・送るとき・ボタンのURL・期限）。
確認 24時間・パスワード作り直し 1時間・code は1回だけ使えるもの。

## つながる前からの利用者

会員だけの機能（名刺カード・ワン友QR・おねがい・予定・成長の記録の画像・もしものときカードをLINEで送る・2匹目からの診断）は、つながる前から使っていた人（その端末にうちの子の記録がある人）は、つながったあとはじめて開いた日から30日そのまま使えます（`accGated`・`graceInfo`）。数えはじめはその端末の `w44x_first`。

その30日のあいだは、登録をすすめます（画面の側でしています。サーバーの作業はありません）：
- トップ（「診断をはじめる」の下）とマイページのアカウントの欄に、黄色の帯「名刺カードなどが登録なしで使えるのは、あと○日（○月○日まで）」と「くわしく」。
- 「くわしく」で開く「登録のおすすめ」のページ：のこりの日数・会員の方が使える機能・登録するとできること・今までの記録はそのまま・診断はこれからも登録なし無料・「会員登録（無料）」「ログイン」「あとで」。登録したけれどメールの確認がまだの人には「確認のメールを見る・もう一度送る」。
- このページは、はじめてつながったとき・のこり7日・最後の日・終わったあと、それぞれ1回だけ自動で開きます（`w44x_grace_seen`。問題に答えている途中・登録の画面では開かない）。
- アクセス解析のイベント `grace_view`（stage＝start／w7／last／end、via＝auto／bar／my）。
- 見本では `?acct=demo&grace=のこりの日数` で試せます（0＝終わったあと）。

## 会員登録・ワンスタを始める日に、いっしょに変えるもの

- `privacy.html` を、会員登録・ワンスタありの版（下書き `privacy-next.html`）の中身に置きかえてください（題の【下書き】と、改定日の【会員登録・ワンスタを始める日】・【確認中：使うサービスの名前と国】を埋める）。今の `privacy.html` は「写真や答えはどこにも送らない」版です。
- 「このサイトについて」の「写真や答えは…どこにも送りません」は、`W44Auth` がつながると自動で「会員の方の記録と、ワンスタの写真・ひとことはサーバーでお預かりします」の文に変わります（`#ab-priv`）。

## 登録のあとの流れ（画面の側でしていること）

- 会員だけの機能を押して登録の案内が出たとき、押そうとしていた機能を覚えておき、登録（メールの確認）が終わったら、その画面にもどって機能を開きます。
- 確認メールのボタンを別の画面で押した人が元の画面にもどると、`currentUser()` を呼び直して、確認できていればそのまま続けます。
- アクセス解析のイベント：`grace_view`（登録のおすすめのページを見た）・`gate_view`（案内を見た）・`sign_up`（登録した）・`verify_complete`（メールの確認まで終わった。via＝link／return）・`login`。

## これから作る会員の機能：記録の自動バックアップ・家族で見る（2026-11-27 決定）

画面の見本：https://claude.ai/artifact/KZosScTpTgQ6Bf8B1yzHuF（まだ index.html には入れていません。サーバーと一緒に作る機能です）

### 1 記録の自動バックアップ

- 会員（メールの確認まで終わった人）の記録を、自動でサーバーに保存します。保存するもの：うちの子・診断の結果・成長の記録・予定・受け取ったワン友・名刺カード・もしものときカード（いまは端末の `w44_` で始まる保存にあるもの）。
- マイページに「記録のバックアップ」：自動で保存していること・最後に保存した時刻・保存しているものの数。
- 新しいスマホでログインしたら、サーバーの記録を端末にもどして「おかえりなさい！ ○○の記録を、このスマホにもどしました」。
- つながる前から端末にある記録は、登録（確認）が終わったときにサーバーへ送ります。

### 2 家族で見る

- マイページに「家族で見る」：家族の一覧（家族をまとめる人＝招待した人・入った日・「まだ開いていません」）と「LINEで家族を招待する」。
- **家族は5人まで**（家族をまとめる人をふくむ）。招待のリンクを開いた人は、無料の会員登録（またはログイン）をして家族に入ります。
- 家族が見られるもの：診断の結果・うちの子のページ・予定・成長の記録・名刺カード・もしものときカード。予定と成長の記録は、家族のだれでも足せます。ほかの家族のメールアドレスは見えません。
- **家族が消せるのは、自分が足した予定・記録だけ**。家族を外せるのは、家族をまとめる人だけ。
- 予定・記録には、だれが足したか（名前と色）を出します。
- **家族が予定・記録を足したら、ほかの家族にお知らせ**：画面のお知らせ（「ゆいさんが、ももの成長の記録を足しました」）と**メール**の両方。メールは1人ずつオン・オフを選べます（最初はオン）。
- プライバシーポリシーに、家族と記録を分け合うこと・家族へのお知らせのメールを書き足します。
