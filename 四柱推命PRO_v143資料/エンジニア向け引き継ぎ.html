Pocket鑑定・四柱推命PRO v143 改修内容と運用

2026-09-25 時点。対象：Pocket鑑定（pocketkantei_final_fixed.zip）と 四柱推命PRO（pro_20260925_v143_fixed.zip）。
同じ内容は各zipの docs/2026-09-25_変更点と運用ガイド.md（Pocket）と CHANGES_20260925.md（PRO）にもあります。

要点

  1. 命式エンジンの修正（Pocket・PRO共通）：節入り判定が北京時間基準で1時間ずれていたのを直しました。大運は必ず「0歳〜立運＝月柱」から始まる形で扱い、年運は立春で切り替えます。
  2. Pocketにアカウント機能を新設：メールアドレス＋パスワードで登録・ログインでき、確認メールのリンクは使いません。データはサーバーに自動保存され、パスワードを忘れても利用者が再設定メールで自分で直せます。
  3. デプロイ前に環境変数が3つ増えます：AUTH_SECRET（必須）、RESEND_API_KEY と MAIL_FROM（パスワード再設定に必須）。デプロイは Git連携 か CLI で行ってください。
  4. PROの印刷用命式表に重大な不具合：立運が1年未満の人の大運が10年ずれて表示されていたので修正しました。過去に出した鑑定書の見直しが必要な場合があります。

運営が定めた四柱推命のルール

実装はすべてこのルールに合わせています。変更する場合は運営の確認が必要です。

  • 大運：必ず0歳の 月柱（第一運） から始まる。第1大運（月柱の次の干支）は立運から始まり、以後10年ごとに切り替わる。
    例：立運0歳8ヶ月 → 0歳〜0歳8ヶ月＝月柱、0歳8ヶ月〜10歳8ヶ月＝第1大運。
  • 年運：立春で切り替わる。
  • 節木運：大運の季節（方合：亥子丑＝冬、寅卯辰＝春、巳午未＝夏、申酉戌＝秋）が変わる時。約30年ごと。10年ごとの大運の節目とは別物。月柱と第1大運の季節が違えば、立運の時点も節木運。

四柱推命エンジンの修正（Pocket・PRO共通）

節入り判定の時差

  • 原因：暦ライブラリ tyme4ts の節気時刻は 北京時間（UTC+8） 基準です。エンジンは日本時間の生まれ時刻をそのまま比べていたので、節入り直前の1時間に生まれた人（約0.2%）で、年柱・月柱・順逆・大運がずれていました。海外生まれは時差の分だけ範囲が広がります（米国東部なら13時間）。
  • 修正：BJ2(r) で出生の瞬間を北京時間に換算します（r.stdMer 未指定は日本 135°）。
    • 年柱・月柱・順逆・立運・大運：換算した時刻で判定
    • 日柱・時柱：従来どおり現地の時刻（真太陽時）で判定
    • W2 の -1/24 は削除
  • Pocketの pro-adapter.js は、出生地の標準子午線を、時刻不明の場合も stdMer として渡します。
  • 真太陽時補正 Q2 は、ブラウザの地域設定・夏時間に左右されない UTC 計算にしました。

大運のデータの持ち方

  • decadeFortunes[]（8本）は 立運以降の10年運だけ です（添字0＝月柱の次の干支）。配列の添字は変えていません。
  • 第一運（月柱）は別オブジェクトです。
    • Pocket：pro.monthDecade。今の大運は curDecade(pro) で取得（立運前は月柱を返す）
    • PRO：monthDuOf(c)、curDu(c)、duListWithMonth(c)
  • daeunIndex>=0 ? … : 0 のように、立運前に第1大運を使う書き方はしないでください。以前の不具合の原因です。
  • 年齢表示：立運の端数月まで出します（Pocket _duSpan 系、PRO duAgeSpan）。
  • 今いる大運の判定：年単位の now.age ではなく、月単位の now.ageMonths で判定します（PRO duIsNow）。

年運

  • annualFortunes[] は西暦年キー（その年の立春〜翌立春）で、生まれた時の年柱の年から並びます。
  • now.year は立春基準の「今年」です（1/1〜立春前は前年）。暦の年は now.calYear（Pocket）です。年運を引く時は now.year を使ってください。

節木運

  • Pocket：setsubokuAnalysis()。PRO：Setsuboku.analyze(opt) に opt.prevBranch（月柱の地支）を追加。
  • 「今」「次の節木運」「前後1年半（自分から話題にしてよい時期）」は、now.ageMonths で月単位に判定します。
  • AIへの説明文を、判定と一致する内容に直しました。以前は「丑辰未戌の大運が曲がり角」と一律に書いていて、判定と食い違っていました。

変更していない点：立運の計算式は比例方式 round(節入りまでの日数 ÷ 節の間の日数 × 120ヶ月) のままです。「3日＝1年」とは最大2ヶ月ほど差が出ます。

保存先（Netlify Blobs ストア pk-accounts）

  • u:<sha256(小文字メール)>：{ email, salt, hash, ver, created, updated, fails, lockUntil, data, reset:{h,exp}, resetSent }
  • r:<JST日付>:<IP>（新規登録数）、f:<JST日付>:<IP>（再設定依頼数）
  • パスワード：scrypt（N=16384, r=8, p=1）＋ソルト。平文は保存しません。
  • トークン：<uid>.<ver>.<期限>.<HMAC-SHA256(AUTH_SECRET)>（365日）。
  • 再設定コード：サーバーには sha256 だけを保存します。
  • data：端末の pk_* キーの文字列です（上限150万文字）。pk_auth / pk_sync_at / pk_did / pk_key / pk_svdraft / pk_svq は送らず、サーバー側でも除外します。
  • 端末の新しいキー：pk_auth（{email, token}。パスワードは保存しない）、pk_sync_at。

PRO固有の修正

【重大】印刷用命式表（meishi-sheet.html）：立運1年未満の人の大運の干支を1つずつ後ろへずらす処理があり、全大運が10年遅れて表示されていました。
例：1963-03-05 06:00 女性（立運0歳6ヶ月）は、乙卯が「10歳6ヶ月〜」と表示されていました（正しくは「0歳6ヶ月〜」）。
ずらす処理は廃止し、先頭に「0歳〜立運＝月柱」の行を必ず出すようにしました。立運0歳◯ヶ月のお客様に出した鑑定書は、見直しが必要な場合があります。

  • 立運前の「今の大運」：9か所で第1大運を使っていたのを、月柱に直しました（五行・通変の巡り、空亡、夫婦の冲、相性、AI鑑定文）。
  • 生まれ年：birthYearOf(c) で入力の生年月日から取ります。以前は、端数月で年をまたぐと月柱の行が1年ずれていました。
  • 早子時モード：日付を進める前の実際の時刻（tzBase）で節入りを判定します。
  • 命式表：年運の「今年」を立春基準に、「今」の判定を月単位にしました。解説文の「立運＝最初の大運」は、「0歳は月柱から、立運で次の10年運へ」に直しました。
  • その他：pklove.js（立運前の年は月柱を使う）、ritsuun.html（教材の用語の修正）。

その他の修正（Pocket）

  • functions/gemini.js：Blobs を使う前の connectLambda(event) が抜けていました。本番で 利用回数の制限が効いていなかった可能性 があります。修正済みです。
  • legal.html（日英）：最終改定日を2026-09-25にしました。
    • プライバシーポリシー：保存場所（端末＋アカウント）、パスワードはハッシュのみ、メール配信事業者（Resend）へメールアドレスのみ送信、アカウント削除の方法
    • 利用規約第3条：アカウントとパスワードの自己管理
  • 登録画面の文言：「当社サーバーには保存しません」を、10言語で実態に合わせて書き換えました。
  • AIへの指示文：大運の年齢を◯歳◯ヶ月で渡し、立運前は月柱を今の大運として渡します。「大運はまだ始まっていない」という表現は削除しました。

未対応・運営判断待ち

  • 確認メールなし：登録時に確認メールを送らない方針のため、打ち間違えたアドレスや他人のアドレスでも登録できます。その場合、再設定メールは届きません。
  • 同期方式：「最後に保存した方が勝つ」方式で、データ全体を上書きします。2台で同時に使うと、片方の変更が上書きされることがあります。
  • トークンの保管場所：ログイン用トークンは localStorage にあります。外部スクリプトを増やす時は、XSS に注意してください。
  • 日次カウンター：r: と f: は自動で消えません。量が増えたら定期削除を検討してください。
  • 計算の仕様（運営判断）：
    • 立運の比例方式
    • 日本のサマータイム（1948〜1951年）は未補正
    • 韓国の1954〜61年の標準子午線127.5°は未反映
    • 大運は8本（立運＋80年）まで
  • 古い仕様書：docs/技術仕様書.html は 2026-08-21 版のままです。Markdown版が最新です。
