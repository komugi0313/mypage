01

概要・設計思想

四柱推命をベースにしたAIチャット型占いアプリ。フクロウのキャラクター「Nico」が、生年月日時から算出した命式をもとに、10言語で「人生として言語化された」鑑定を返す。四柱推命の計算はクライアント内で決定論的に確定し、AIには計算させない。

Principle 01

計算はコード / 表現はAI

命式・大運・十二運・通変・五行・空亡・節木運はローカルで確定。AIには確定データだけを渡し、推論・計算をさせない。存在しない関係の捏造を構造的に防ぐ。

Principle 02

安全は決定論 / 話題はAI

自傷・重い相談の検知は正規表現で決定論的に。話題（恋愛/家族/仕事）の意図解釈だけAI分類器で補助する「ハイブリッド」。

Principle 03

専門用語を出さない（既定）

通常の鑑定では干支・十神・五行などを一切出さず平易語のみ。ユーザーが理屈を求めた時だけ「理論モード」で専門用語を使う。

04

四柱推命エンジン

計算

computeChart(profile) が命式 chart を確定。内部で window.PersonBazi(...)（pro-bazi.js）を呼ぶ。profile は { y, m, d, hh, mi, tu, sex }（tu=時刻不明、sex='male'|'female'）。出生地（経度）選択で真太陽時補正。海外都市の経度も保持。

chart オブジェクト（主要フィールド）

chart.pro.pillars[]年月日時の4柱。各 { label, ganzhi, branch, terrain(十二運), tenStar(通変), hiddenStems }
.decadeFortunes[]大運。{ startAge, endAge, startYear, ganzhi, branch, terrain, tenStar }
.startFortune立運 { years, months, forward }（forward=順行/逆行）
.annualFortunes[]年運
.now現在時点 { age, year, daeunIndex }
.dayMaster日主 { stem, element }
chart.fav用神（喜忌）。五行キー { 木:'喜'|'忌'|'中庸', … }
chart.five五行バランス
✓

命式は同じ生年月日なら決定論的に一意。ポケット鑑定とPRO版（別エンジン）でも四柱・十二運・通変・大運・空亡が一致することを検証済み。

06

鑑定パイプライン answer(q)

answer(q)
 ├─ classifyRisk(q)   … 決定論の安全判定（自傷/犯罪/性的/支配）
 │     → crime/sex/control は即・定型の安全応答（AI非経由）
 ├─ _aiClassify(q)    … 軽量AI分類器（人物/関係の話題）※LITE・x-pk-classify（課金対象外）
 │     → window._aiTopicHint に格納（失敗時は正規表現 _classifyTopic へ）
 └─ _answerCore(q, risk)
       ├─ buildSystemPrompt()  … 命式データ＋ふるまいルールを組み立て
       ├─ Gemini 呼び出し（smartフラグで LITE/DEEP ルーティング）
       └─ 出力ガードパイプライン（浄化）

安全判定 classifyRisk(q)

正規表現 RE_SELFHARM / RE_CRIME / RE_SEX / RE_CONTROL。死別・他者の自殺・過去の自殺未遂（生存）は RE_BEREAVE_OTHER / RE_OWN_PAST_ATTEMPT で自傷から除外（現在念慮 RE_CUR_IDEATION がある時のみ selfharm）。「十二運の死」は非自傷と判定。

話題分類（ハイブリッド）

_needsAiClassify(q) が人物・関係語を検出 → _aiClassify（temperature:0・maxOutputTokens:300・4.5s timeout）。_mapAiTopic(o,q) がマップし、決定論のサニティネットで補正（夫/妻/彼＝本人の恋愛・家族ではない、等）。_effectiveTopic(q) はAIヒント優先。

出力ガードパイプライン（適用順）

_stripThinkLeak → _extractChips → _softenJargon(含 _softenTwelveStage)
 → _stripInternalLabels → _stripScaffold → _stripLeadThink
 → _stripHan → _stripPreamble → _stripFufu

_softenTwelveStage は十二運の「死・病・墓・絶・胎・衰」等を意味を保ったまま安全表現へ。JARGON_WRAP（多言語の専門用語リスト）で漏れを検知・浄化。チップ（サジェスト）は本文と分離抽出。

システムプロンプト buildSystemPrompt()

命式データを英語のデータブロック群＋ふるまいルールとして連結：lifeArcBlocksetsubokuBlockromanceBlockloveMandateBlockhealthBlockluckyBlocktodayBlocktopicFocus_heavyRulecrisisBlock ＋ 文体/言語/専門用語禁止ルール。

AIモデル運用（ハイブリッド）

役割モデル用途
LITEgemini-2.5-flash-lite通常会話・分類器（安価・高速）
DEEPgemini-3.6-flash恋愛・重い相談・決断・人生・韓国語など品質重視
上位（任意）gemini-3.1-pro-preview最高品質・低速高コスト

クライアントは x-pk-deep:'1' の時のみ DEEP を使う（smart フラグ＝deep/back/offscope/恋愛/韓国語/決断/重い/自傷/Nico自身/人生 で判定）。分類器は x-pk-classify:'1'（日次カウント外・常にLITE）。

!

Gemini 3.x の落とし穴：thinkingConfig.thinkingBudget:0 は 3.x で 400 エラー。3.x では送らない（サーバー側でも除去）。思考でトークンを消費するため maxOutputTokens を 3200〜4200 に確保する。

クライアント直接接続（体験/デモ）：window.PK_DIRECT_KEY があれば generativelanguage.googleapis.com へ直接。本番は Function 経由（/api/gemini → /.netlify/functions/gemini）でキーを秘匿。

08

サーバーレス関数 functions/gemini.js

役割：APIキー秘匿 ＋ サーバー側レート制限 ＋ モデルルーティング。

  • モデル：MODEL_LITE（env GEMINI_MODEL）/ MODEL_DEEP（env GEMINI_MODEL_DEEP）。x-pk-deep==='1' で DEEP。
  • レート制限：x-pk-device＋IP を Netlify Blobs（getStore('pk-usage')）に日次カウント。超過で 429（Geminiを呼ばずAPI浪費防止）。x-pk-classify==='1' はカウント外。
  • 413ガード：「最後のユーザー発話」が MAX_BODY(12000) 超で 413。全体 900,000 超でも 413。システムプロンプトは正規に大きいので本文長で判定。
  • 3.x互換：gemini-3 系は thinkingConfig を除去し maxOutputTokens を確保。
  • DEEPフォールバック：DEEP 失敗（課金枯渇429・5xx）時は LITE に一度だけフォールバックし必ず返す。
  • オリジンチェック：process.env.URL と origin/referer を照合。

10

多言語対応（i18n）

  • UI辞書 I18N（T() / pick() で現在言語を取得）。10言語：jaenzhztkoviesptidth
  • AIプロンプト末尾に「Reply in {language}」。ルールは英語＋各言語の例。出力は選択言語のみ（他言語混入を禁止）。
  • 言語は起動時に navigator.language から自動判定 → pk_lang。
  • 用語辞書・危機相談先・ラッキー要素・性格タイプ・干支動物などすべて10言語ローカライズ。
11

安全設計（クライシス）

  • 自傷検知：RE_SELFHARM 該当時、crisisBlock() が最優先の応答指示を注入（傾聴優先・助言や占いをしない・各言語のヘルプライン提示）。
  • ヘルプライン HELPLINE：10言語×各国の実在窓口（日本 いのちの電話 / 米988 / 中国 / 台湾 / 韓国 / ベトナム / スペイン / ブラジル / インドネシア / タイ）。
  • 重い相談 _heavyRule：死別・自殺（家族/友人）・過去の自殺未遂・虐待・望まない妊娠等に専用ルール（第三者の事情を捏造しない・断定しない・責めない）。
  • フォールバック safeReply：AIが使えない時も安全に応答。

14

データ・プライバシー

  • 会話・プロフィールは端末内localStorageのみ。サーバーに個人プロフィールは保存しない。
  • サーバーが保持するのはレート制限用の「端末ID＋IP＋日次カウント」を短期間のみ（個人特定用途ではない）。
  • App Privacy / Data Safety 申告時は、収集項目として「生年月日時（機能上必須）・端末ID・IP」を正確に記載。
15

ビルド・デプロイ

  • ビルド不要。brand/ をそのまま Netlify にデプロイ（静的＋functions/）。
  • Netlify 側で GEMINI_API_KEY（本番キー）を環境変数に設定。
  • Geminiプロジェクトは前払い残高（課金）を有効化（3.6-flash利用時。残高枯渇で429）。
  • netlify.toml：/api/gemini → /.netlify/functions/gemini。Blobs は通常デプロイで自動有効。
