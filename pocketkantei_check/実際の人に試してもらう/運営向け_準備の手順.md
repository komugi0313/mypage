# 実際の人に試してもらう：運営の準備（30分ほど・1回だけ）

試す人は **送られてきたリンクを開くだけ** で使えます（キーを貼る・設定するは無し）。
そのために、運営が1回だけ下の準備をします。

## 1. テスト用の Gemini キーを新しく作る（5分）
1. Google AI Studio（aistudio.google.com）→「Get API key」→ 新しいキーを作る。
2. **有料の枠（課金を有効にしたプロジェクト）で作る**（無料の枠は、入力した内容が Google の改善に使われることがあるため）。
3. Google Cloud の「予算とアラート」で、月の上限（例：3,000円）とメールの知らせを設定する。
4. **前にチャットに貼ったキーは、このタイミングで無効にする。**

費用の目安：1人が1日10回ほど話すと、1日10〜30円ほど。10人×1週間で 1,000〜2,000円ほど。

## 2. Netlify に「試してもらう版」のサイトを作る（10分）
今のテスト用サイトとは **別のサイト** にします（今のサイトはそのまま）。
1. Netlify →「Add new site」→「Import an existing project」→「GitHub」。
2. リポジトリ `komugi0313/mypage` を選ぶ。
3. Branch：`claude/practical-dijkstra-duyy0a`
4. **Base directory：`pocketkantei_check/tester-site`**（ほかの欄は空のままでよい。設定はフォルダの中の `netlify.toml` に書いてあります）
5. 「Deploy」を押す。

## 3. 環境変数を入れる（5分）
Netlify のそのサイト →「Site configuration」→「Environment variables」→「Add a variable」。

| 名前 | 入れるもの |
|---|---|
| `GEMINI_API_KEY` | 1 で作った新しいキー |
| `PK_INVITES` | 招待コード（カンマ区切り。1人に1つ。別にお送りした「招待コード.txt」をそのまま貼る） |
| `PK_ADMIN` | 会話の記録を見る時の合言葉（16文字以上。だれにも教えない） |
| `PK_LOG` | `1`（会話を記録して、運営が決定的なミスを探す。試す人の案内に「記録します」と書いてあります） |

入れたら「Deploys」→「Trigger deploy」→「Deploy site」でもう一度出し直す。

> 招待コードやキーは、GitHub（公開されています）には絶対に書かない。Netlify の環境変数にだけ入れる。

## 4. 動くか確かめる（3分）
自分のスマホで `https://<サイトの名前>.netlify.app/?invite=<招待コードの1つ>` を開き、生年月日を入れて1回話してみる。返事が出ればOK。

## 5. 試す人に送る
- 1人に1つ、招待リンク `https://<サイトの名前>.netlify.app/?invite=<その人のコード>` を送る。
- 一緒に「試す人への案内」（その人の言語）を送る。
- **コードは人ごとに分ける**（だれのやり取りか分かる・1人だけ止めたい時に、そのコードだけ消せる）。

## 6. 試している間（毎日5分）
- その日の会話の記録：ブラウザで `https://<サイトの名前>.netlify.app/api/relay?admin=<合言葉>&day=2026-11-05` を開く（日付は見たい日）。中身をファイルに保存して送ってもらえれば、決定的なミス（くり返し・理屈ボタンの失敗・一方的・聞かれたことに答えない など）を数えます。
- 試す人から届いたスクリーンショットと一言を、1か所にまとめておく。

## 7. 終わったら
- 環境変数 `PK_INVITES` を消す（全員のリンクが使えなくなる）か、サイトごと消す。
- テスト用の Gemini キーを無効にする。
- 記録はテストの振り返りが終わったら消す（Netlify の「Blobs」→ `pk-tester` を削除）。

## 上限（変えたい時は環境変数で）
- 1人1日の呼び出し：200回（1回の返事で2〜4回呼ぶので、1日50回ほど話せる）→ `PK_PER_DAY`
- 全員の合計の1日：2,000回 → `PK_ALL_DAY`
