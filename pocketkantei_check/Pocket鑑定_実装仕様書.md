# Pocket鑑定 実装仕様書（2026-09-29 版）

この文書は、Pocket鑑定（10言語の四柱推命チャット・PWA／Netlify）の**正本の仕様書**です。
同じ zip の `docs/` にほかの資料もありますが、内容が食い違う時は**この文書を優先**してください。
- `2026-09-25_変更点と運用ガイド.md`：変更の経緯を日付順にまとめた記録
- `Pocket鑑定_技術仕様書.md`：命式の計算の詳しい仕様

## 0. 絶対に守ること（最初に読んでください）

1. **APIキーや秘密の値をコードに書かない。** 秘密の値は、Netlify の環境変数だけに置きます。対象は、Gemini・Resend・RevenueCat のキー、`AUTH_SECRET`、決済のURLのひな形です。この zip にはキーは入っていません。
2. **デプロイは Git 連携か Netlify CLI（`netlify deploy`）で行う。** 管理画面への zip のドラッグ＆ドロップでは、`functions/`（AI・アカウント・課金）と Netlify Blobs が動きません。
3. **`AUTH_SECRET` は一度決めたら変えない。** 変えると、全員のログインが切れます。
4. **`PK_TRUST_PLAN_HEADER` を本番で設定しない。** 設定すると、アプリの自己申告のプランを信用してしまい、誰でも有料プランを名乗れます。テスト専用の値です。
5. **料金・回数・利益の数字を勝手に変えない。** 運営が決めた数字です（「3. 料金と回数」「4. 利益65%」）。
6. **AIへの指示文の並び順を崩さない。** 毎回変わる情報（時刻・その1通の話題など）は必ず最後に置きます（「6.3」）。崩すと、キャッシュ割引が効かなくなり、原価が上がります。
7. **画面の文言は10言語をそろえて直す。** ja・en・zh（簡体）・zt（繁体）・ko・vi・es・pt・id・th です。1言語だけ直すと、その言語だけ古い表示が残ります。
8. **つらい気持ち・危機の相談への返事は、どの上限でも止めない。** AIが使えない時も、アプリが相談窓口つきの返事を出す作りを保ちます（`safeReply`・`HELPLINE`）。
9. **更新したら、Service Worker のキャッシュ名を上げる。** `sw.js` の `pocket-kantei-v14` → `v15` のようにします。上げないと、利用者の端末に古い画面が残ります。
10. **Gemini の本番プロジェクトは前払いで運用し、残高の通知を必ず受け取れるようにする。** 残高が切れると、全員のチャットが止まります（「10.2」）。

## 1. 全体の構成

| ファイル | 役割 |
|---|---|
| `index.html` | アプリ本体（画面・10言語の文言・AIへの指示文・回数・課金の画面） |
| `lp.html` | 紹介ページ（未登録の人は最初にここへ） |
| `legal.html` | 利用規約・プライバシーポリシー・特定商取引法の表記（日英） |
| `pro-bazi.js` / `pro-adapter.js` / `bazi.js` | 命式の計算（PRO v184 と同じロジック。Pocket独自は出生地の時差補正のみ） |
| `sw.js` | Service Worker（オフライン用のキャッシュ。`/api/` は対象外） |
| `functions/gemini.js` | AIの中継（APIキーを隠す）・回数の上限・AI原価の上限 |
| `functions/auth.js` | アカウント（登録・ログイン・同期・パスワード再設定・プラン照会・ウェブ決済・ウェブ解約） |
| `functions/billing.js` | 購読の通知の受け取り（RevenueCat の Webhook）→ アカウントにプランを記録 |
| `functions/push-lib.js` | ニコからのメッセージ（プッシュ通知）の中身：文面づくり（AI）・送信（Firebase）・受け取り箱（「11.2」） |
| `functions/nico-push.mjs` | 毎時0分に動く予約関数。送信をバックグラウンド関数に頼む |
| `functions/nico-push-background.mjs` | バックグラウンド関数（最長15分）。その時刻の人に文面を作って送る |
| `netlify.toml` | `/api/gemini`・`/api/auth`・`/api/billing` → 各関数への転送 |
| `package.json` | 関数が使う `@netlify/blobs`（^8.1.0） |

**データの保存先（Netlify Blobs）**
- ストア `pk-accounts`：アカウント（`u:<uid>`）、登録数（`r:<日>:<IP>`）、再設定依頼数（`f:<日>:<IP>`）
- ストア `pk-usage`：回数・原価の数（キーの一覧は「5.4」）

`uid` は、メールアドレス（小文字）の SHA-256（16進64桁）です。ログイン用トークンの先頭64桁も、この `uid` です。

## 2. デプロイと環境変数

### 2.1 手順
1. リポジトリに zip の中身を置き、Netlify と Git 連携します（または `netlify deploy --prod`）。
2. 「2.2」の環境変数を設定します。
3. デプロイ後に「9. 公開前チェック」を上から順に確認します。

### 2.2 環境変数
| 変数 | 必須 | 値 | 未設定の時 |
|---|---|---|---|
| `GEMINI_API_KEY` | **必須** | 本番用の Gemini API キー | チャットが動かない |
| `AUTH_SECRET` | **必須** | 32文字以上のランダム文字列（例：`openssl rand -hex 32`）。**一度決めたら変えない** | 登録・ログインが動かない（`NO_SECRET`） |
| `RESEND_API_KEY` | **必須** | Resend の API キー（送信元ドメインを認証しておく） | パスワード再設定メールが送れない（`NO_MAIL`） |
| `MAIL_FROM` | **必須** | 例：`Pocket Kantei <no-reply@72k.ai>` | 同上 |
| `REVENUECAT_WEBHOOK_AUTH` | 課金の開始時に必須 | 長いランダム文字列。RevenueCat の Webhook の「Authorization header」と同じ値 | 購入してもプランが反映されない |
| `PK_PRODUCTS` | 推奨 | ストアの商品ID → プラン。例：`{"pk_std_monthly":"std","pk_std_annual":"std","pk_pro_monthly":"pro","pk_pro_annual":"pro","pk_vip_monthly":"vip","pk_vip_annual":"vip"}` | 商品IDに `vip`・`pro`・`std` の語が入っていれば自動で判定 |
| `TELECOM_CHECKOUT_URLS` | ウェブ決済の開始時に必須 | テレコムクレジットの決済画面のURLのひな形。キーは `std_m` `std_y` `pro_m` `pro_y` `vip_m` `vip_y` の6つ。`{uid}` `{email}` `{lang}` は置き換えられる | ウェブ版の購入ボタンが「準備中」になる |
| `PK_AI_PRICES` | 推奨 | AIの料金（ドル／100万トークン）。例：`{"lite":{"in":0.10,"out":0.40,"cached":0.025},"deep":{"in":0.50,"out":3.00,"cached":0.125}}`。**gemini-3.6-flash の正式な料金に入れ直すこと** | 上の例の値（deep は仮の値） |
| `PK_FX` | 任意 | 1ドル＝円（既定 150）。円安になったら上げる | 150 |
| `PK_COST_BUDGET_JPY` | 任意 | 1人・1か月のAI原価の上限（円）。既定 `{"std":592,"pro":1204,"vip":2000}` | 既定値 |
| `PK_DEEP_RESERVE_JPY` | 任意 | 本格鑑定1回分として先に取っておく原価（既定 4円） | 4 |
| `GEMINI_MODEL` / `GEMINI_MODEL_DEEP` | 任意 | 既定は `gemini-2.5-flash-lite` ／ `gemini-3.6-flash`（運営決定） | 既定値 |
| `PK_IGNORE_SANDBOX` | 任意 | `1` でテスト購入を反映しない。**Apple の審査中は設定しない**（審査はテスト購入で行われるため） | テスト購入も反映する |
| `FCM_PROJECT_ID` / `FCM_CLIENT_EMAIL` / `FCM_PRIVATE_KEY` | ニコのメッセージの開始時に必須 | Firebase のサービスアカウント（JSON）の `project_id` / `client_email` / `private_key`。秘密鍵は `\n` を含む1行のまま貼ってよい | ニコのメッセージが届かない（文面は作られない） |
| `PK_PUSH_MODEL` | 任意 | ニコのメッセージの文面を作るモデル。既定は `GEMINI_MODEL`（軽量） | 既定値 |
| `PK_PUSH_ACTIVE_DAYS` | 任意 | 最後にアプリを開いてから、この日数を過ぎた人には送らない。既定 `{"free":14,"paid":45}` | 既定値 |
| `PK_TRUST_PLAN_HEADER` | **本番では設定しない** | テスト専用 | ― |

`URL` は Netlify が自動で設定します。関数は、これを使って他サイトからの呼び出しを断ります。

### 2.3 画面に出るエラーコード（アカウント関連）
| コード | 原因 | 対処 |
|---|---|---|
| `NO_SECRET` | `AUTH_SECRET` が未設定、または短い | 環境変数を設定して再デプロイ |
| `NO_STORE` | Netlify Blobs に接続できない | Git連携／CLIでデプロイ。`@netlify/blobs` を確認 |
| `HTTP404` | 関数が未デプロイ | `functions/` と `netlify.toml` を含めて再デプロイ |
| `NO_MAIL` | `RESEND_API_KEY` か `MAIL_FROM` が未設定 | 環境変数を設定 |
| `MAIL_FAIL` | Resend への送信に失敗 | Resend 管理画面のログを確認 |

## 3. 料金と回数（運営決定 2026-09-03。変更しないこと）

| プラン | 内部ID | 月額（税込） | 年額（税込） | 米ドルの目安 | 本格鑑定 |
|---|---|---|---|---|---|
| Standard | `std` | ¥2,900 | ¥31,900 | ≈$19.99 | 月50回 |
| Pro（いちばん人気） | `pro` | ¥5,900 | ¥64,900 | ≈$39.99 | 月100回 |
| VIP | `vip` | ¥9,800 | ¥107,800 | ≈$69.99 | 月175回 |

- **無料お試し：** 3日間・合計15通、1日5通まで。サーバー側でも、端末ごとに1日5回・同じIPで40回に制限します。
- **本格鑑定として数えるもの：** 恋愛・結婚、決断、重い相談、人生の方向についての相談（`index.html` の `_answerCore` で、変数 `counted` が true になるもの）。
- **数えないもの：**
  - 雑談
  - 「なぜ？」の確認
  - あいづち
  - つらい気持ち・危機の相談
  - 韓国語で品質のために上位モデルを使うだけの時
- **数える期間：** 暦の月ではなく、**支払い期間ごと** です（月額はその期間、年額は1年を12等分）。月の途中で買った人が2か月分使えないようにするためです。
- **本格鑑定を使い切った時：**
  - Nico がチャットで伝えます（`DEEP_OUT`・`DEEP_OUT_VIP`）。雑談は続けられます。
  - Standard と Pro は、0.7秒後に料金プランのシートを出します。VIP は案内だけです。
- **無料お試しが終わった時：** お知らせの文を出した後、料金プランのシートを出します。
- **ウェブ版の価格の表示：** 日本語は「¥2,900 / 月（税込）」、ほかの言語は「¥2,900 (≈$19.99) / month」です。アプリ版は、ストアが返す現地の価格（`priceString`）を表示します。

## 4. 利益65%を守る仕組み（運営決定。変更しないこと）

**決まり：** どんな使い方をされても、手数料（アプリ30%・テレコムクレジット5%）を引いた後の手取りの **65%以上** を利益として残します。

- **1人・1か月のAI原価の上限（`COST_BUDGET`）：**
  - Standard ¥592・Pro ¥1,204・VIP ¥2,000
  - 計算：年額÷12÷1.1×（1−0.30）×（1−0.65）。手取りがいちばん少ない条件です。
- **原価の計算：** AIの返事にある実際の使用量（`usageMetadata` の入力・キャッシュ済み入力・出力・思考のトークン数）× 料金（`PK_AI_PRICES`）× 為替（`PK_FX`）で、1回ごとに計算してサーバーに積み上げます。
- **割り当て方：**
  1. 本格鑑定の残り回数分の原価（1回¥4）を先に取っておきます。本格鑑定は必ず回数どおり使えます。
  2. 残りを「残り÷区切りの残り日数」ずつ、毎日、雑談・「なぜ？」に割り当てます。
  3. 1回ごとに「見込み原価を足しても今日の分を超えないか」を確かめ、超えるなら 429 `DAILY_BUDGET` を返します。
  4. アプリは「雑談はまた明日。本格的な相談はこのまま聞けるよ」と表示します（`BUDGET_NOTE`）。
- **検証済み：** 31日間、毎日止まるまで使い続けても、AI原価は上限の内側に収まりました。アプリ手数料30%で、利益は月額68%・年額65%です（`tests/budgettest.js`）。
- **実測の原価（2026-09-26、実際のAIで201回）：** 雑談1回 約¥0.15、本格鑑定1回 約¥2.00。キャッシュ割引が効いた入力の割合は、雑談74%・本格鑑定50%でした。
- 採算表（アーティファクト「Pocket鑑定 採算表」、または `pocketkantei_check/採算表.html`）で、前提を変えて試算できます。

## 5. サーバー（`functions/`）

### 5.1 `/api/gemini`（`gemini.js`）
アプリから受け取るヘッダー：
| ヘッダー | 意味 |
|---|---|
| `x-pk-auth` | ログイン用トークン。プランは**このトークンからアカウントの購読を引いて**決めます。`x-pk-plan` は使いません |
| `x-pk-device` | 端末ID |
| `x-pk-deep: 1` | 上位モデル（`gemini-3.6-flash`）を使う |
| `x-pk-nocount: 1` | 上位モデルだが本格鑑定に数えない（「なぜ？」・あいづち・危機の相談など） |
| `x-pk-retry: 1` | 品質のための作り直し（数えない） |
| `x-pk-classify: 1` | 話題の判定（常に軽量モデル、出力300トークンまで） |

**判定の順番：**
1. **無料：** 端末5回・IP40回／日
2. **有料の本格鑑定：** 区切りごとに `DEEP_QUOTA`（50／100／175回）まで。超えたら 429 `DEEP_QUOTA`
3. **有料の数えない上位モデル：** 安全上限として1日100回まで（アカウントごと）
4. **有料の雑談：** 安全上限として端末300回・IP1000回／日
5. **話題の判定：** 無料は端末30回・IP200回／日、有料は端末600回・IP2000回／日
6. **AI原価の上限：** 「4」のとおり

**アプリへ返すヘッダー：**
- `x-pk-win`：今の区切り
- `x-pk-deep-used`：使った本格鑑定の回数

**上位モデルが失敗した時：** 軽量モデルで1回だけやり直します。

### 5.2 `/api/auth`（`auth.js`、すべて POST・JSON の `action` で切り替え）
| action | 入力 | 返すもの・動き |
|---|---|---|
| `register` | email, password(8〜128文字), data | token, plan。同じIPから1日20件まで |
| `login` | email, password | token, data, plan。5回続けて失敗すると15分ロック |
| `save` / `load` | token（save は data も） | 端末データ（`pk_*` の値）の保存と読込 |
| `status` | token | plan（購入・復元の直後に確かめる用） |
| `change` | token, password, newPassword | 新しい token。ほかの端末はログアウトになる |
| `delete` | token, password | アカウントを削除する |
| `forgot` | email, lang | 再設定メールを送る。登録の有無は分からない応答にしている。1時間3通まで |
| `reset` | code, newPassword | 30分・1回限り |
| `checkout` | token, plan, period(`m`/`y`), lang | ウェブ決済のURL。未設定なら `NOT_READY` |
| `cancel` | token | ウェブ版（テレコムクレジット）の解約。**`telecomStopRecurring()` は未実装（「7.3」）** |
| `push_set` | token, pushToken, on, mode(`auto`/`fixed`), hour(0〜23), tz, lang, platform | ニコのメッセージのオン・オフと送る時刻（`auto`＝ニコにおまかせ・既定、`fixed`＝決まった時刻 `hour`）。`pushToken` は端末の通知トークン（`token` はログイン用なので別の名前） |
| `push_inbox` | token, tz | 届いたニコのメッセージ（最新10件・7日まで）。アプリを開いた時に呼ぶ。最後に開いた日時と、今いる地域（`tz`）も記録し直す |

**プランの返し方：** `plan` は `{plan:'free'|'std'|'pro'|'vip', start, expires, willRenew, store}` です。期限が過ぎていれば `free` を返します。

### 5.3 `/api/billing`（`billing.js`）
RevenueCat の Webhook の受け口です。
- **認証：** `Authorization` ヘッダーが `REVENUECAT_WEBHOOK_AUTH`（または `Bearer ＋同じ値`）と一致する時だけ受け付けます。
- **通知の種類ごとの処理：**
  - 付与：`INITIAL_PURCHASE`・`RENEWAL`・`PRODUCT_CHANGE`・`UNCANCELLATION` など
  - 解約（`CANCELLATION`）：期限までは使えます。
  - 期限切れ（`EXPIRATION`）：free に戻ります。
  - 引き継ぎ（`TRANSFER`）：移動元から移動先へ購読を付け替えます。
- **無視するもの：** 古い通知・匿名の購入（`$RCAnonymousID`）・不明な商品。
- **書き込み先：** `u:<uid>` の `rec.sub = {plan, product, start(purchased_at_ms), expires, willRenew, store, env, eventTs}`

### 5.4 ニコのメッセージのキー（`pk-accounts` ストア。「11.2」）
| キー | 中身 |
|---|---|
| `ps:<uid>` | 設定と記録 `{on, token, platform, mode, hour, target, tz, lang, bucket, lastDay, hist, seen}`（`target`＝おまかせで次に送る時刻） |
| `pb:<UTCの時>:<uid>` | その時刻（UTC）に送る人の目印。毎時、その時刻の人だけを読む |
| `pi:<uid>` | 受け取り箱 `{items:[{id, text, ts}]}` |
アカウントを削除すると、この3つも消えます。

### 5.5 `pk-usage` のキー（参考）
| キー | 中身 |
|---|---|
| `d:` `i:` | 無料の1日の数（端末・IP） |
| `q:<区切り>:<uid>` | 本格鑑定の数 |
| `c:<区切り>:<uid>` | 区切り内のAI原価（1/100円） |
| `cd:<日>:<uid>` | その日のAI原価（1/100円） |
| `w:` | 数えない上位モデルの1日の数 |
| `l:` `li:` | 有料の雑談の1日の数 |
| `k:` `ki:` | 話題の判定の1日の数 |

`r:` `f:`（`pk-accounts` 側の日ごとの数）とあわせて、自動では消えません。量が増えたら、古い日付のキーを定期的に消してください。

## 6. アプリ（`index.html`）

### 6.1 画面の流れ
- **未登録で開いた時：** 必ず `lp.html` へ移動します。「はじめる」→ `index.html?start=1`（登録）、「ログイン」→ `index.html#login`。
- **登録：** 生年月日などと、メールアドレス＋パスワード（確認つき）。確認メールは送りません。
- **パスワード再設定：** メールのリンク（`index.html#reset=<uid>.<code>`）→ 新しいパスワード → 自動でログイン。
- **データ：** アカウントに自動保存します（保存のたびに4秒後、アプリを閉じる時にも）。起動時に、ほかの端末での更新を取り込みます。
- **開発者用の体験モード：** 自分のAPIキーを直接使う欄と、テスト用のプラン切替です。**一般の利用者には出ません**。`?dev=1` で開いた端末だけに表示します。

### 6.2 課金の画面（`renderPlanExtras`・`PKBilling`）
- **アプリ（Capacitor）：**
  - `window.Capacitor.Plugins.Purchases`（RevenueCat の Capacitor プラグイン）と `window.PK_RC_KEYS={ios:'appl_…',android:'goog_…'}` がある時だけ購入できます。
  - RevenueCat の `appUserID` は、アカウントの `uid` です。**購入はログイン中だけ** です。
  - 「購入を復元」（Apple の必須要件）と「購読の管理・解約」（ストアの設定画面を開く）を出します。
  - **アプリの中にはカード決済を出しません**（Apple の審査ガイドラインのため）。
- **ウェブ版：**
  - 購入ボタン → `checkout` → テレコムクレジットの決済画面へ移動します。
  - 解約はプラン画面の「解約する」から、利用者が自分で行います。**運営の手作業は不可** という方針です。
- **表示するもの：**
  - 月額／年額の切り替え
  - 自動更新の説明（10言語）
  - 利用規約・プライバシーポリシーへのリンク
  - 次回の更新日
  - マイページに「今月の本格鑑定：あと○回」
- **プランの正本はサーバーです。** アプリは、サーバーから受け取った `plan` を `applyServerPlan()` で反映します。

### 6.3 AIへの指示文（`buildSystemPrompt`）の並び順 ※崩さないこと
Gemini は、前回と先頭から同じ部分の入力を割引します。そのため、**変わらない順** に並べています。
1. **ルール**（言語ごとに全員共通、約1万4千5百トークン）
2. **この人の情報**（`nameLine`・`cultureBlock`・`proBlock`・`pastBlock`・`zodiacBlock`・`monthBlock`・`romanceBlock`・`nayinBlock`・`voidReleaseBlock`・`favLogicBlock`）
3. **相談の内容で出し入れするもの**（`healthBlock`・`turningBlock`・`yearFactBlock`・`lifeArcBlock`・`setsubokuBlock`・`luckyBlock`）
4. **長期記憶** `memLine`（6通ごとに更新）
5. **`[FOR THIS MESSAGE …]` から後ろ：** 現在時刻 `timing`・`_heavyRule`・`crisisBlock`・`aftercareBlock`・`_todayGate`・`topicFocus`・`spotlightBlock`・`loveMandateBlock`

**新しい情報を足す時：** 毎回変わるものは必ず 5 に入れます。`tests/prefix.js` で、一致率が下がっていないか確かめてください。
- 同じ人の3時間後で、92%以上
- 同じ言語の別の人で、ルールの部分が共通

### 6.4 AIの返事の後処理（10言語の品質を守る仕組み）
- **作り直しの条件：** 言語が違う（`_wrongLang`）、仏暦の年・一字の専門語が出た（`_jargonLeak`）、前の返事の丸写し（`_nearDupOfHistory`）。この時は、上位モデルで1回だけ作り直します。
- **仕上げ：**
  - 前の返事と同じ段落は取り除きます（`_dropRepeatedParas`）。
  - 連続した読点・名前の無い「님」・中国語の置き換えの崩れを直します（`_finalTidy`）。
  - 専門用語をやさしい言葉に置き換えます（`_softenJargon`。韓国語の助詞も直す）。
  - 本文に紛れた質問候補は、ボタンとして取り出します（`_extractChips`）。
- **相手の誕生日：** 10言語の日付の書き方を読み取り、相性の計算に使います（`_parseDateAny`・`chatPartnerScan`）。AIに渡すデータには、本人の生年月日と相手の生年月日（「本人ではない」と明記）を分けて書きます。
- **相談窓口：** 端末の地域から国を推定し、その国の窓口を出します（26か国）。一覧に無い国では「地域の緊急番号へ」とだけ案内します（`_deviceCountry`・`HL_LOCAL`）。

### 6.5 命式の計算（変えないこと）
- エンジンは、PRO v184 と同じロジックです。
  - Pocket独自は、真太陽時補正の基準を出生地の実効子午線（`stdMer`）にしたことと、`lunarToSolar` を足したことだけです。
- **時差：** 出生地ごとに IANA タイムゾーン（`tz`）を持っています。生まれた日時の実際の UTC 差で計算します（過去の夏時間・標準時の変更も反映）。
- **大運：** 必ず0歳の月柱から始まります（第一運＝月柱、0歳〜立運）。年運は立春で切り替わります。節木運は、大運の季節（方合）が変わる時です。
- **検証：**
  - v184 と一致（2万件）
  - 独立した天文計算と一致（6,240件）
  - 大運の一括チェック（1万件）で不一致0件

## 10. 運用の注意（使われすぎ・障害・デモの扱い）

### 10.1 Gemini の使われすぎへの備え
- **1人あたりは止まる仕組みがあります：**
  - 無料は1日5回（同じIPで40回）です。
  - 有料は、本格鑑定の回数とAI原価の上限（「3」「4」）で止まります。
  - 話題の判定にも1日の上限があります。
- **大勢が同時に使って Google が混雑した時（Google が 429 などを返した時）：**
  - 上位モデルが失敗したら、軽量モデルで1回だけやり直します。
  - それでも失敗したら、アプリは「いまアクセスが集まっていて混み合っているみたい。少し時間をおいて送ってね」と表示します。画面は止まりません。
- **利用者が増えてきたら、Google の利用枠（1分あたりのリクエスト数・トークン数）を上位の枠に上げてください。** AI Studio のプロジェクト画面から申請できます。枠が足りないと、上の「混み合っている」表示が増えます。

### 10.2 必ずしてほしい設定（費用の暴走を防ぐ最後の安全装置）
- **Gemini の本番プロジェクトは、前払い（プリペイド）の残高で運用し、次のどちらかを選んでください。**
  - 自動チャージをオンにする場合：予算アラートも必ず設定し、使いすぎに早く気づけるようにします。
  - 自動チャージをオフにする場合：入れた金額以上は絶対に使われません（費用の上限の蓋になります）。その代わり、残高が切れると全員のチャットが止まります。
- **残高が切れると、全員のチャットが「うまく届かなかった」という表示になります。** 利用者には原因が分かりません。残高の通知は必ず受け取れるようにしてください。
- **もう一つの蓋「月の支出上限（spend cap）」にも注意してください。** Google AI Studio のプロジェクトには、月ごとの支出上限を設定する機能があります（https://ai.studio/spend）。
  - 上限に達すると、その月は全員のAIが止まります（エラー `429 … exceeded its monthly spending cap`）。
  - 利用者には「いま鑑定が混み合っている」と表示されます。
  - テスト中に実際にこの上限に達しました（2026-09-29）。
  - 本番では、想定の利用者数に余裕を持たせた金額にし、上限に近づいた時の通知を必ず受け取れるようにしてください。

### 10.3 回数を記録する場所（Netlify Blobs）が使えない時
- 回数や原価は、Netlify Blobs（`pk-usage`・`pk-accounts`）に記録しています。
- **Blobs に一時的につながらない時は、回数と原価の上限が効きません。** サービスを止めないため、チャットは通す作りです。応答ヘッダーに `x-pk-ratelimit: degraded` が付きます。
- めったに起きませんが、この間の費用は「10.2」の前払いの上限で守られます。Netlify の関数のログで `degraded` が続いていないか、ときどき確認してください。

### 10.4 デモ・体験モードについて
- **デモ応答（作り置きの鑑定文）はありません。** AIにつながらない時は、正直なエラー文と再送ボタンを出します。
- **開発者用の体験モード**（自分のAPIキーで直接つなぐ欄・テスト用のプラン切替）は、一般の利用者には出ません。`?dev=1` を付けて開いた端末だけに出ます。
  - 入れたAPIキーは、その端末の中だけに保存されます。動かす費用はその人自身のキーで払われ、こちらの費用や回数には影響しません。
  - テスト用のプラン切替で有料プランを選んでも、サーバーはアプリが名乗るプランを信用しないため、有料にはなりません。
- **`window.PK_DIRECT_KEY` をコードに書かないでください。** 書くと、サイト全体がそのキーで直接つながり、キーが誰にでも見えてしまいます。
- **この zip には、APIキーはどこにも入っていません。** 本番のキーは、Netlify の環境変数 `GEMINI_API_KEY` だけに置きます。

## 11. そのほかの機能と、実装時に気をつけること

### 11.1 ニコとの距離が縮まる仕組み（`toneBlock`・長期記憶）
- **これまでに送ったメッセージの数（`pk_tmsg`）で、ニコの話し方が3段階で変わります。**
  - 0〜19通：出会ったばかり。ていねい語（です・ます）
  - 20〜59通：打ち解けてきた。親しみのある話し方、軽い冗談
  - 60通〜：いつもの相棒。くだけた話し方（タメ語）。時には親友としての正直なひと言も
  - 10言語それぞれに合わせて変わります。韓国語は 존댓말 から 반말 へ。タイ語はていねいな語尾を保ちます。
- **長期記憶（`pk_mem`）：** 6通ごとに、会話の要点（仕事・人間関係・気にしていること・約束など）を軽量モデルでメモにまとめ、次からの返事に生かします（「そういえば、あの件どうなった？」など）。
- **`pk_tmsg` と `pk_mem` はアカウントに保存されます。** 機種を変えても、距離感と記憶は引き継がれます。
- **最初からになる時：**
  - メニューの「会話をリセット」を押した時
  - 生年月日などを変えて、別の人の命式になった時
  - この2つの時は、距離感と記憶も最初からになります（今の仕様です）。
- **キャッシュとの関係：** `toneBlock` は指示文の先頭側にあります。ただし、変わるのは20通目と60通目の2回だけなので、キャッシュ割引への影響はほとんどありません。

### 11.1b ニコの姿勢 ― 都合よく肯定しない、本物の友だち（運営決定 2026-09-29）
一般的なAIチャットは、質問に都合よく肯定しがちです。心地よく、つい使い続けてしまいますが、ニコはそれだけにしません。肯定・応援、時には厳しい助言、寄り添い、根拠のある説明を、その人がいま必要としているものに合わせて使い分けます。関係が深まるほど「この子は本当のことを言ってくれる」と信頼されることを目指します。
- **指示文の rule 1f（`A REAL FRIEND, NOT A YES-MACHINE`）：** 毎回、次の4つから主な対応を1つ選ばせます。
  - (A) 応援：良いことをした時。**何が良かったか**と、命式のどの強みが出たかを具体的に言う。
  - (B) はっきり助言：無謀・危険・不公平なことへの賛成を求められた時や、同じ失敗の繰り返し。**賛成しない。** 最初の1〜2文で本音を言い、理由（命式・時期・本人の話）と、より安全な具体策を示す。
  - (C) 寄り添う：つらい・疲れた・自分を責めている時。まず気持ちを受け止め、説教しない。「私ってダメ」には、命式と本人の話から**根拠のある反論**をする（空っぽのお世辞は禁止）。
  - (D) 根拠つきの説明：「なんで？」「正直に」「私の欠点は？」。耳の痛い部分も含めて、命式から具体的に説明する。
- **正直さのルール（出会ったばかりの段階から）：**
  - 「〜だよね？」「私悪くないよね？」には、まずその質問に正直に答える（はい／一部は／正直に言うと、いいえ）。
  - 理由のない褒め言葉（「すごい！」「最高の才能！」）は禁止です。
  - 喜ばせるために運気を良く言うことも禁止です。
  - 人としては味方でいながら、意見には反対してよい。
  - 段階で変わるのは**言い方だけ**です（出会ったばかり＝ていねいに「正直にお伝えすると…」、親しい相棒＝親友の率直さ）。
- **仲良くなる工夫：** ニコの小さな個性（小さな成功に大喜びする、睡眠やご飯を少し心配する、自分の意見を持っている）を毎回同じに保つ。前に聞いた話を思い出す。本人の**成長に気づいて口に出す**（「前より自分を責めなくなったね」）。
- **健全な関係：** 引き止めない。「ニコがいないとだめ」と思わせない。友だち・家族・専門家に頼ることを応援する。アプリを閉じた後に、軽く・強くなっていることを目指します。
- **上位モデルへ回す話題を追加しました（`index.html`）。** 軽量モデルは長い指示文の細かい部分を守りきれず、肯定しがちだったためです。次の話題は上位モデル（`gemini-3.6-flash`）で答え、本格鑑定として数えます。

### 11.1c 10言語・32人の会話テストで直したこと（2026-09-29）

### 11.2 ニコからのメッセージ（プッシュ通知。アプリ版だけ）
**運勢の案内はしません。** ニコが友だちのように話しかけるメッセージです（運営決定 2026-09-29）。
- **送る時刻（運営決定 2026-09-29）：**
  - **ニコにおまかせ（既定・おすすめ）：** その人の地域の朝8時〜夜9時のあいだで、毎日ちがう時間帯に送ります。時間帯は「朝8〜9時／お昼12時／午後3〜4時／夕方6〜7時／夜8〜9時」から、前の日と違うものを選びます。深夜・早朝には送りません。
  - **時刻を決める：** 利用者が1時間単位で選んだ時刻に、毎日送ります。
- **中身：** 1日1回届きます。「おはよう」「ご飯食べた？」「今日もおつかれさま」「あの件どうなった？」など。
  - 文面は毎回、軽量モデルがその場で作ります。材料は、ニコとの距離感（`pk_tmsg`）、会話のメモ（`pk_mem`）、最近の会話、ニックネーム、曜日・時間帯です。
  - 距離感で話し方が変わります（出会ったばかり＝ていねい語 → 親しい相棒＝タメ語）。チャットと同じ3段階です。
  - 時間帯に合わない話（朝8時に「お昼食べた？」）はしません。直近10通と似た文面は作り直します。
  - 言語が違う・長すぎる文面は送りません（2回作って駄目なら、その日は送りません）。
- **ロック画面への配慮：** 通知は家族や職場の人にも見えることがあります。ほかの人の名前、家族、面接や転職、健康、お金、恋愛、つらい話は文面に入れません。「あの件」のようにぼかします。
- **つらい状況の人：** 会話のメモや最近の会話から、とてもつらい時期だと分かる時は、「ここにいるよ」という静かなメッセージだけにします。
- **仕組み：**
  1. アプリで「受け取る」を押す → 通知の許可 → 端末の通知トークンを `push_set` でアカウントに記録
  2. 毎時0分に `nico-push` が動き、`nico-push-background` がその時刻の人に送る
  3. 送ったメッセージは受け取り箱（`pi:`）にも入る → アプリを開いた時・通知をタップした時に `push_inbox` で取り出し、ニコの発言としてチャットに足す（同じものは二度足さない）
- **送らない人：** オフにした人／通知を消した端末（Firebase が「宛先なし」と返したら自動でオフ）／最後にアプリを開いてから、無料の人は14日・有料の人は45日を過ぎた人（`PK_PUSH_ACTIVE_DAYS`）。
- **条件：** アプリ版とアカウント（ログイン）が必要です。ウェブ版では「アプリ版で使えます」と表示されます。
- **費用：** 実際のAIで測ると、1通 約0.01円（60通で0.6円）。1人・1か月でも約0.3円です。有料の人の分は、1か月のAI原価の上限（「4」）に含めて数えます。
- **国をまたいでも時刻と中身がずれない仕組み：**
  - 時刻は、スマホの地域設定（タイムゾーン。例：`Asia/Tokyo`、`America/New_York`）で数えます。日本の時刻では数えません。
  - 旅行や引っ越しで地域が変わった時は、アプリを開いた時にその地域に合わせ直します（`push_inbox` の `tz`）。
  - 夏時間の切り替えも、送るたびに地域の時刻を確かめて付け直します。
  - 文面は、送るその時のその人の地域の時刻と曜日を材料に作ります。
  - **最後の確認：** 時間帯に合わない言葉が入っていたら送らずに作り直します。10言語それぞれの言葉で確かめます（`timeOk`）。
    - 朝の言葉（おはよう・朝ごはん・Good morning・早安・좋은 아침 など）は4〜11時だけ
    - お昼の言葉（お昼ごはん・lunch・午餐・점심 など）は11〜14時だけ
    - 夜の言葉（こんばんは・おやすみ・晩ごはん・dinner・晚安・저녁 など）は17〜3時だけ
  - **曜日も確かめます（`dayOk`）。** 間違った曜日は信頼を失うので、10言語の曜日の言い方で確かめ、合わない時は送らずに作り直します。
    - 今日ではない曜日の名前（金曜に「水曜」、「明日は土曜」も含む）は送りません。
    - 「週の始まり」は月曜だけ、「週末」は木〜日曜だけです。
    - 曜日に触れるのは4回に1回くらいに、コードで決めています。毎回だと決まり文句に見えるためです。触れない回は、曜日も週末も話題にしないよう指示します。
    - 実際のAIで、10言語×月〜日の70通を試しました。曜日の取り違えは0件、曜日に触れたのは13通でした（`tests/pushlive3.js`）。
- 実際のAIで10言語×7つの時刻（8・9・12・15・18・20・21時）を試し、言語・時間帯・ロック画面の配慮が守られていることを確かめました（`tests/pushlive.js`）。

### 11.3 登録時のアンケート（国ごとの傾向データ。必ず集めて保存するもの）
- 登録の時に、メールアドレス・関心のある話題・知ったきっかけ・使う頻度・職業・性別・年代・国・言語を集めます。**使い道：国・地域ごとの傾向を知り、サービスをより良くするため、また次の商品開発の情報にするため**（運営決定 2026-09-29）。
- **送り先はエンジニアが本番の保存先（バックエンド／Google のサーバー）につなぎます。** 今のコードは仮の送り先として Netlify Forms（`/` へ `form-name=pk-signup` で送信。`index.html` の `_svPost()`）を使っています。
  - `_svPost(body)` の送り先を本番のURLに差し替えてください（中身は `application/x-www-form-urlencoded` の文字列）。本番に切り替えたら、`index.html` 末尾の Netlify 用の隠しフォーム `<form name="pk-signup" …>` は削除して構いません。
  - 送る項目：uid（端末ID）、名前、email、topics、interests、source、freq、job、sex、age（年代）、country（出生地の国）、lang（表示言語）。国別・言語別の集計に使います。
  - 送れなかった分は端末に残り、次に開いた時に送り直されます（`pk_svq`）。送り先は、成功した時に 2xx を返すようにしてください。
  - Google Apps Script で受ける場合は、ブラウザから直接送れる形（CORS）か、`functions/` に中継用の関数を置いて、サーバー側から転送してください。受け口のURLや鍵をコードに直接書かず、環境変数に入れてください。
- **プライバシーポリシーに記載済みです**（集める項目・保存先の Google のクラウド・使い道・削除の依頼先）。保存先を Google 以外にする場合は、プライバシーポリシーも直してください。

## 12. 分かっている制限（公開してから改善を検討するもの）
- **タイ語：** 「来月は？」の直後に「今月は？」と聞くと、今月を来月と取り違えることがまれにあります（ほかの言語は直りました）。
- **本格鑑定の残り回数の表示：** 端末の表示は、サーバーから届いた最新の値です。別の端末で使った直後は、少しずれることがあります。回数の上限そのものは、サーバーが正しく守ります。
- **無料お試しの日数と回数は、端末ごとに数えています。** 端末のデータを消すとやり直せますが、サーバーの1日の上限（端末5回・IP40回）は効きます。
- **AIの返事は毎回変わります。** 後処理でよくある崩れは防いでいますが、100%ではありません。問い合わせで届いたおかしな返事は、`tests/unitguard.js` に例を足して直していくのが確実です。
