- **料金について：** 送信数の上限は **Resend 側の料金プラン** によるものです。アプリに回数制限を作ったわけではありません。Resend の無料プランは送信数に上限があります（目安として1日100通・月3,000通。**最新の料金は Resend 公式サイトで確認してください**）。利用者が増えて上限を超えると、その日は再設定メールが送れなくなるので、有料プランへの切り替えを検討してください。
- **更新の配信：** Service Worker のキャッシュ版は `pocket-kantei-v5` です。以後も更新時には `sw.js` の `CACHE` を上げてください。

## 3. 四柱推命エンジンの修正（`pro-bazi.js` / `pro-adapter.js`）

### 3.1 節入り判定の時差（不具合修正・PRO版にも同じ修正）
- **原因：** 暦ライブラリ tyme4ts の節気時刻は **北京時間（UTC+8）** 基準です。エンジンは日本時間（や各国の現地時刻）をそのまま比べていたため、日本生まれなら節入りの1時間前に生まれた人の年柱・月柱・順逆・大運がずれていました（ランダム2万件中44〜45件、約0.2%）。米国東部生まれなら13時間分ずれます。立運の日数計算だけは `-1/24` で日本時間に合わせてありましたが、命式そのものはずれていました。
- **修正：** `BJ2(r)` で出生の瞬間を北京時間の時計に換算します（`(120 − 標準子午線) × 4分` ずらす。`r.stdMer` が無ければ日本 135° とみなす）。
  - **年柱・月柱・順逆・立運・大運：** 換算した時刻で判定
  - **日柱・時柱：** 従来どおり現地の時刻（真太陽時）で判定
  - `W2` の `-1/24` は削除（換算を `BJ2` に一本化）
- `pro-adapter.js` は、出生地の標準子午線（`place.mer`）を **時刻不明の場合も** `stdMer` として渡します（経度補正は時刻が分かる時だけ）。
- 真太陽時補正 `Q2` の分の加減算を、ブラウザの地域設定・夏時間に左右されない UTC 計算にしました。
- **検証：** 日本生まれ2万件で、変わったのは節入り直前の45件だけでした。変わった例を独立した天文計算（ephem）の節入り時刻と照合し、修正後が正しいことを確認しています。

### 3.2 大運のデータ構造（ルール：大運は必ず0歳の月柱から）
- エンジンの `decadeFortunes[]`（8本）は **立運以降の10年運だけ** です（添字 0 ＝ 月柱の次の干支）。**この配列の添字は変えていません。**
- 第一運（0歳〜立運＝月柱）は別オブジェクト `pro.monthDecade` で持ちます。
  - `{ isMonth:true, startAge:0, months:0, endAge, endMonths, startYear, ganzhi, stem, branch, stemElement, branchElement, tenStar, terrain }`
- **今の大運** は `curDecade(pro)`（`window.curDecade`）で取得します。立運前（`now.daeunIndex === -1`）なら月柱を返します。
  - `daeunIndex >= 0 ? decadeFortunes[i] : monthDecade` を直接書かないでください。以前 `:0`（第1大運）にしていた箇所が不具合の原因でした。
- **年齢の表示：** 立運の端数月まで出します（例：立運0歳8ヶ月 → 第一運 0歳〜0歳8ヶ月、第1大運 0歳8ヶ月〜10歳8ヶ月）。`index.html` の `_duSpan / _duSpanJ / _duSpanE` を使います。
- **「今その大運にいるか」：** 年単位の `now.age` ではなく、月単位の `now.ageMonths` で判定します。
- **立運の計算式は変更していません：** `round(節入りまでの日数 ÷ 節と節の間の日数 × 120ヶ月)` の比例方式です。一般的な「3日＝1年」とは最大2ヶ月ほど差が出ます。流派としての扱いは運営に確認済みではないため、変える場合は運営判断が必要です。

### 3.3 年運（ルール：立春で切り替え）
- `annualFortunes[]` は西暦年をキーにした干支（その年の立春〜翌立春）です。一覧は **生まれた時の年柱（立春基準）の年から** 始まります（1/1〜立春前の生まれは前年から）。
- `now.year` は **立春基準の「今年」** で、1/1〜立春前は前年になります。暦の年は `now.calYear` です。
  - 年運を引く時は必ず `now.year` を使ってください。画面に「今日の日付」として出す時は `calYear` を使います。

### 3.4 節木運（せつぼくうん）※定義は運営確認済み
- **定義：** 大運の季節（方合：亥子丑＝冬、寅卯辰＝春、巳午未＝夏、申酉戌＝秋）が変わる時。約30年ごとです。**大運の節目（10年ごと）とは別物** として扱います。
- 第一運（月柱）も大運の一つなので、月柱と第1大運の季節が違えば、立運の時点も節木運です。
- 実装は `setsubokuAnalysis()`（`index.html`）です。「今」「次の節木運」「前後1年半（自分から話題にしてよい時期）」は `now.ageMonths` で月単位に判定します。
- 喜神の季節なら「発展の30年」、忌神なら「備えの30年」と読み、十二運が墓・絶・胎の大運や空亡の大運は「強まる」扱いにしています（従来どおり）。

## 4. アカウント機能（新設）

### 4.1 利用者から見た動き
| 場面 | 動き |
|---|---|
| 未登録で開く | 毎回 `lp.html` を表示（以前はLP既読の印 `pk_seen_lp` で登録画面に直行していた） |
| LP「はじめる」 | `index.html?start=1` → 登録画面。命式の入力＋メール・パスワード（8文字以上・確認つき）。**確認メールのリンクは使わず即登録** |
| LP「ログイン」／登録画面下のリンク | `index.html#login` → ログイン画面。成功するとサーバーのデータで端末を置き換える |
| パスワードを忘れた | ログイン画面 → 「パスワードを忘れた方」→ メールアドレス入力 → 再設定メール（表示言語で送信・10言語）→ `index.html#reset=<uid>.<code>` → 新しいパスワード → 自動ログイン |
| 通常利用 | ログイン状態は端末に保持し、次回は自動ログイン。データは自動でサーバーへ保存 |
| メニュー「データの引き継ぎ・バックアップ」 | 先頭にアカウント欄：今すぐ保存／パスワード変更／ログアウト／アカウント削除。未ログインの既存ユーザーは、ここからアカウントを作って今のデータを移せる |
| メニュー「退会する」 | ログイン中は「アカウント削除」（パスワード確認つき）へ案内。サーバーのデータも消す |
| パスワード欄 | すべてに「表示／非表示」の目のボタン。送信時は自動で非表示に戻す |

### 4.2 API：`POST /api/auth`（`functions/auth.js`）
共通：JSON `{ action, ... }` → `{ ok:true, ... }` または `{ ok:false, code }`。他サイトからの呼び出し（Origin不一致）は 403。

| action | 入力 | 出力 | 備考 |
|---|---|---|---|
| `register` | `email, password, data` | `token, email` | 既存なら 409 `EXISTS`。同一IPから1日20件まで |
| `login` | `email, password` | `token, email, data, updated` | 5回続けて失敗すると15分ロック（429 `LOCKED`）。未登録アドレスでも同じ 401 `BAD_LOGIN` |
| `save` | `token, data` | `updated` | データ全体を上書き保存 |
| `load` | `token` | `email, data, updated` | |
| `change` | `token, password, newPassword` | `token` | `ver` が上がり、他端末のトークンは無効になる |
| `delete` | `token, password` | ― | アカウントとデータをサーバーから削除 |
| `forgot` | `email, lang` | ― | 登録の有無にかかわらず `ok:true`。1アカウント1時間3通・同一IP1日30件まで |
| `reset` | `code, newPassword` | `token, email, data, updated` | リンクは30分有効・1回限り。`ver` が上がる |

### 4.3 保存先とデータ形式（Netlify Blobs ストア `pk-accounts`）
| キー | 中身 |
|---|---|
| `u:<sha256(小文字メール)>` | `{ email, salt, hash, ver, created, updated, fails, lockUntil, data, reset:{h,exp}, resetSent:[時刻] }` |
| `r:<JST日付>:<IP>` | その日の新規登録数 |
| `f:<JST日付>:<IP>` | その日の再設定依頼数 |

- **パスワード：** `scrypt(N=16384, r=8, p=1, 64byte)`＋ランダムなソルト。平文は保存しません。
- **トークン：** `<uid>.<ver>.<有効期限>.<HMAC-SHA256(AUTH_SECRET)>`（365日）。`ver` が一致しなければ無効です。
- **再設定コード：** ランダム24バイトを送信し、サーバーには sha256 だけを保存します。
- **`data`：** 端末の `pk_*` キーの文字列です（上限 1,500,000 文字）。ただし次のキーは送らず、サーバー側でも除外します。
  - `pk_auth` / `pk_sync_at` / `pk_did` / `pk_key` / `pk_svdraft` / `pk_svq`

### 4.4 端末側（`index.html`）
- 新しい localStorage キー：
  - `pk_auth`：`{ email, token }`。**パスワードは保存しません**（パスワードはブラウザのパスワード保存機能に任せる）
  - `pk_sync_at`：最後に同期したサーバーの `updated`
- **自動保存：** `saveProfile` / `saveMsgs` をラップして4秒後にまとめて保存し、アプリを閉じる時（`visibilitychange: hidden`）にも保存します。
- **起動時：** サーバーの `updated` が `pk_sync_at` より新しければ（他の端末で更新されていれば）取り込んで再読み込みします。
- **ログアウト：** 最後に保存してから、端末のデータを消します（言語・配色・LP既読は残す）。その後ログイン画面へ移ります。
- **振り分け（冒頭のスクリプト＋`boot`）：**
  - プロフィールあり → チャット画面
  - `#reset=` → 再設定画面
  - `#login` → ログイン画面
  - `?start=1` → 登録画面
  - それ以外 → `lp.html`

### 4.5 既知の制約（運営判断・今後の課題）
- **登録時に確認メールを送りません**（運営の方針）。そのため、打ち間違えたアドレスや他人のアドレスでも登録できます。その場合、再設定メールは届きません。
- **同期は「最後に保存した方が勝つ」方式で、データ全体を上書きします。** 2台で同時に使うと、片方の変更が上書きされることがあります。
- ログイン用トークンは localStorage にあるため、XSS があれば盗まれる可能性があります（一般的なSPAと同じ前提）。外部スクリプトを増やす時は注意してください。
- 日次カウンター（`r:` と `f:`）は自動では消えません。量が増えたら、定期削除を検討してください。
- メールの本文の見た目は簡易なHTMLです。ブランドに合わせる場合は `auth.js` の `sendResetMail` と `MAIL_TEXT` を編集してください。
