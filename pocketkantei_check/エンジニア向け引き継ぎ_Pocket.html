Pocket鑑定 改修内容と運用（2026-09-25／09-26追記）

2026-09-26 時点。対象：Pocket鑑定（pocketkantei_final_fixed.zip）。
同じ内容は zip 内の docs/2026-09-25_変更点と運用ガイド.md にもあります。

要点

  1. 命式エンジンの修正：節入り判定が北京時間基準で1時間ずれていたのを直しました。大運は必ず「0歳〜立運＝月柱」から始まる形で扱い、年運は立春で切り替えます。
  2. ベースエンジン v184 と同じロジック・時差対応・10言語対策（9/26）：エンジンを PRO v184 に揃え、出生地のタイムゾーンを IANA で正しく扱い、AI回答の言語・年号の崩れを防ぐ仕組みを入れました。詳しくはこちら。
  3. アカウント機能を新設：メールアドレス＋パスワードで登録・ログインでき、確認メールのリンクは使いません。データはサーバーに自動保存され、パスワードを忘れても利用者が再設定メールで自分で直せます。
  4. デプロイ前に環境変数が3つ増えます：AUTH_SECRET（必須）、RESEND_API_KEY と MAIL_FROM（パスワード再設定に必須）。デプロイは Git連携 か CLI で行ってください。

運営が定めた四柱推命のルール

実装はすべてこのルールに合わせています。変更する場合は運営の確認が必要です。

  • 大運：必ず0歳の 月柱（第一運） から始まる。第1大運（月柱の次の干支）は立運から始まり、以後10年ごとに切り替わる。
    例：立運0歳8ヶ月 → 0歳〜0歳8ヶ月＝月柱、0歳8ヶ月〜10歳8ヶ月＝第1大運。
  • 年運：立春で切り替わる。
  • 節木運：大運の季節（方合：亥子丑＝冬、寅卯辰＝春、巳午未＝夏、申酉戌＝秋）が変わる時。約30年ごと。10年ごとの大運の節目とは別物。月柱と第1大運の季節が違えば、立運の時点も節木運。

四柱推命エンジンの修正

節入り判定の時差

  • 原因：暦ライブラリ tyme4ts の節気時刻は 北京時間（UTC+8） 基準です。エンジンは日本時間の生まれ時刻をそのまま比べていたので、節入り直前の1時間に生まれた人（約0.2%）で、年柱・月柱・順逆・大運がずれていました。海外生まれは時差の分だけ範囲が広がります（米国東部なら13時間）。
  • 修正：BJ2(r) で出生の瞬間を北京時間に換算します（r.stdMer 未指定は日本 135°）。
    • 年柱・月柱・順逆・立運・大運：換算した時刻で判定
    • 日柱・時柱：従来どおり現地の時刻（真太陽時）で判定
    • W2 の -1/24 は削除
  • pro-adapter.js は、出生地の標準子午線を、時刻不明の場合も stdMer として渡します。
  • 真太陽時補正 Q2 は、ブラウザの地域設定・夏時間に左右されない UTC 計算にしました。

大運のデータの持ち方

  • decadeFortunes[]（8本）は 立運以降の10年運だけ です（添字0＝月柱の次の干支）。配列の添字は変えていません。
  • 第一運（月柱）は別オブジェクト pro.monthDecade で持ちます。今の大運は curDecade(pro) で取得します（立運前は月柱を返す）。
  • daeunIndex>=0 ? … : 0 のように、立運前に第1大運を使う書き方はしないでください。以前の不具合の原因です。
  • 年齢表示：立運の端数月まで出します（_duSpan / _duSpanJ / _duSpanE）。
  • 今いる大運の判定：年単位の now.age ではなく、月単位の now.ageMonths で判定します。

年運

  • annualFortunes[] は西暦年キー（その年の立春〜翌立春）で、生まれた時の年柱の年から並びます。
  • now.year は立春基準の「今年」です（1/1〜立春前は前年）。暦の年は now.calYear です。年運を引く時は now.year を使ってください。

節木運

  • 実装は index.html の setsubokuAnalysis() です。第1大運は月柱と季節を比べます。
  • 「今」「次の節木運」「前後1年半（自分から話題にしてよい時期）」は、now.ageMonths で月単位に判定します。
  • AIへの説明文を、判定と一致する内容に直しました。以前は「丑辰未戌の大運が曲がり角」と一律に書いていて、判定と食い違っていました。

変更していない点：立運の計算式は比例方式 round(節入りまでの日数 ÷ 節の間の日数 × 120ヶ月) のままです。「3日＝1年」とは最大2ヶ月ほど差が出ます。

2026-09-26 追記：v184 との整合・時差・10言語

エンジンを v184 に揃えた

  • pro-bazi.js は PRO v184 のエンジンが土台です。Pocket独自の変更は次の2点だけです。
    • 真太陽時補正 Q2 を stdMer（出生地の実効子午線）基準にしたこと。v184 は日本専用で 135° 固定のため、そのままだと海外生まれの命式がずれます（5000件中1636件）。
    • lunarToSolar を追加したこと。
  • pro-adapter.js の fukyuList・gogyoBalance を v184 版にしました。共通の27関数は v184 と同一です。
  • 日本の出生では v184 と 1667件中 不一致0件です。旧 Pocket とは2万件中 不一致0件でした（柱・通変・十二運・蔵干・司令・立運・大運・年運・五行・元命）。

時差（出生地のタイムゾーン）

  • 原因：固定の標準子午線と自動の夏時間で時差を出していたため、過去の制度変更を反映できていませんでした（日本1948〜51年の夏時間、中国1986〜91年、韓国1954〜61年の UTC+8:30、英国・メキシコ・ブラジル・ロシア・シンガポール・マレーシアなど）。4160件中140件がずれていました。
  • 修正：PLACES に IANA タイムゾーン名（tz）を追加しました。tzOffsetMin() が Intl.DateTimeFormat からその日時の実際の UTC 差を求め、mer = UTC差(分)÷4 としてエンジンへ渡します。tz が無い時は従来の方式に戻ります。
  • 検証：独立した天文計算（ephem・zoneinfo）と照合し、全地点で6240件中 不一致0件です。

AI回答（10言語）

  • 大運の西暦をデータに明記しました（decadeYears()）。AIに年を計算させません。
  • YEAR_RULE で次の3点を指示します。
    • 西暦の数字だけを使う（タイの仏暦などは禁止）
    • 「A〜B」の期間は A に始まり B で替わる
    • 西洋の星座・生まれた曜日は禁止
  • 次の場合は賢いモデルで一度だけ作り直します。
    • 言語が違う（_wrongLang）
    • 仏暦の年が出た、または中国語の簡単モードで一字の専門語（「害」「未」など）が出た（_jargonLeak）
    挨拶の場合は、その言語の定型の挨拶に切り替えます。
  • 専門語の置き換え（_softReplace）は、韓国語の単語の途中・中国語の重複・韓国語の助詞を正しく扱います。仕上げ（_finalTidy）では「,,」、名前なしの「님,」を消し、韓国語の「별자리」（西洋星座の意味）を「타고난 별」に置き換えます。
  • 本文に漏れた質問候補（"…" / "…" や改行区切り）は、提案ボタンとして回収します。スペイン語・ポルトガル語は性別に合わせた文法で話します。挨拶の出力上限は 1400 にしました。

保存先（Netlify Blobs ストア pk-accounts）

  • u:<sha256(小文字メール)>：{ email, salt, hash, ver, created, updated, fails, lockUntil, data, reset:{h,exp}, resetSent }
  • r:<JST日付>:<IP>（新規登録数）、f:<JST日付>:<IP>（再設定依頼数）
  • パスワード：scrypt（N=16384, r=8, p=1）＋ソルト。平文は保存しません。
  • トークン：<uid>.<ver>.<期限>.<HMAC-SHA256(AUTH_SECRET)>（365日）。
  • 再設定コード：サーバーには sha256 だけを保存します。
  • data：端末の pk_* キーの文字列です（上限150万文字）。pk_auth / pk_sync_at / pk_did / pk_key / pk_svdraft / pk_svq は送らず、サーバー側でも除外します。
  • 端末の新しいキー：pk_auth（{email, token}。パスワードは保存しない）、pk_sync_at。

未対応・運営判断待ち

  • 確認メールなし：登録時に確認メールを送らない方針のため、打ち間違えたアドレスや他人のアドレスでも登録できます。その場合、再設定メールは届きません。
  • 同期方式：「最後に保存した方が勝つ」方式で、データ全体を上書きします。2台で同時に使うと、片方の変更が上書きされることがあります。
  • トークンの保管場所：ログイン用トークンは localStorage にあります。外部スクリプトを増やす時は、XSS に注意してください。
  • 日次カウンター：r: と f: は自動で消えません。量が増えたら定期削除を検討してください。
  • 計算の仕様（運営判断）：
    • 立運の比例方式
    • （9/26 解決）日本のサマータイム・韓国の UTC+8:30 時代などの過去の時差は、IANA タイムゾーンで反映済み
    • 大運は8本（立運＋80年）まで
  • 表示の細部（未変更）：区切りの「・」は全言語共通です。英語などの命式シートでは文中に漢字（例：「Protect 木・水」）が出ます。
  • 古い仕様書：docs/技術仕様書.html は 2026-08-21 版のままです。Markdown版が最新です。
