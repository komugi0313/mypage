# Pocket鑑定 四柱推命エンジン検査レポート（2026-09-25）

比較したもの：
- `pocketkantei_final.zip`（Pocket鑑定）の `pro-bazi.js` / `pro-adapter.js` / `index.html`
- `pro____20260925_v142.zip`（四柱推命PRO v142）の `app-pro.html` 内のエンジンと `setsuboku.js`

## 結論（先に要点）

| 項目 | 判定 |
|---|---|
| 大運の干支・順行/逆行・立運年齢（通常の生まれ時刻） | **エンジンv142と完全一致・正しい** |
| 年運（年ごとの干支） | エンジンと一致・正しい |
| 節木運ロジック | エンジンの setsuboku.js v1.1 と同じ判定式 |
| **大運が「0歳＝月柱」から始まっていない** | **NG（修正済み）** |
| **節入り前後1時間（海外生まれは最大13時間）の命式がずれる** | **NG・エンジンv142にも同じ不具合（Pocket側は修正済み）** |

大運の計算を担う関数（`computeChart`）は、Pocket鑑定とエンジンv142で**同じコード**です。違いは、韓国語のラベルと、韓国の標準子午線・夏時間テーブル（KMER/KDST）が付いていることだけでした（Pocketは出生地の子午線を常に渡すため、韓国用の処理は実際には働きません）。
サンプル9件でも、2万件のランダムな生年月日でも、エンジンと Pocket の大運・立運・年運は完全に一致しました。

## 見つかった不具合

### ① 大運の第一運＝月柱（0歳〜立運）が無い【ルール違反・修正済み】
- エンジンの `decadeFortunes` は「立運後の大運」だけを持っています。エンジンv142のアプリ側（`curDuYear`）では「0歳〜立運＝月柱」を第一運として先頭に追加していますが、**Pocket鑑定にはこの処理がありません**でした。
- 影響：大運一覧・人生年表が立運年齢（例：4歳）から始まり、0歳〜の月柱が表示されない。AIに渡す「人生の章（LIFE ARC）」「過去の運（PAST LUCK）」にも子ども時代の月柱の期間が入っていない。立運前の人（相性で入力する子どもなど）は「大運はまだ始まっていない」とAIに伝えていた。
- 13歳以上の本人の「今の大運」は、立運は最大でも10歳なので**値そのものは正しく**出ていました。

**修正内容**
- `pro-adapter.js`：`monthDecade()`（第一運＝月柱 0歳〜立運）と `curDecade()`（立運前なら月柱を返す）を追加。AIへの説明を「0歳〜立運は月柱」に変更し、「まだ始まっていない」という文言は削除。
- `index.html`：大運一覧と人生年表の先頭に「0-◯ 月柱（第一運＝月柱）」を追加。LIFE ARC・PAST LUCK・相性の大運タグ・転機の年・太過判定も、立運前は月柱を使うように統一。
- 既存の `decadeFortunes` の添字は変えていないので、節木運などへの影響はありません。

### ② 節入り判定が北京時間基準になっている【エンジンv142にも同じ不具合】
- 暦ライブラリ（tyme4ts）の節入り時刻は**北京時間（UTC+8）**です。エンジンは日本時間の生まれ時刻をそのまま比べているため、**節入りが1時間早く扱われて**います。
  - 例：1990年の立春は日本時間 2/4 11:14 ですが、ライブラリ上は 10:14 になっています。
- 立運の日数計算（`W2`）だけは `-1/24`（1時間ずらす）で日本時間に合わせてあり、立運年齢は正しく出ていました。ただ、**年柱・月柱・順逆・大運の干支**はこの補正を通っていません。
- 影響（修正前の実例）：

| 生まれ | 正しい命式 | 修正前 |
|---|---|---|
| 1990-02-04 10:30 東京 女 | 己巳 丁丑・順行・大運 戊寅〜 | 庚午 戊寅・逆行・大運 丁丑〜（年柱・月柱・大運が全部ずれる） |
| 1990-02-04 08:00 ニューヨーク 男 | 庚午 戊寅・順行・大運 己卯〜 | 己巳 丁丑・逆行・大運 丙子〜 |

- 日本生まれでは、節入り直前の1時間（年に12回）に生まれた人だけが影響を受けます（ランダム2万件中45件＝0.22%）。海外生まれでは時差の分だけ範囲が広がり、米国東部では節入り前の13時間が対象になります。

**修正内容（`pro-bazi.js`）**
- 生まれた瞬間を北京時間に換算する関数 `BJ2` を追加（標準子午線が指定されていない場合は日本時間135°とみなします）。**年柱・月柱・順逆・立運・大運**はこの換算した時刻で判定し、**日柱・時柱**は従来どおり現地の時刻（真太陽時）で判定します。
- `W2` の `-1/24` は、換算を上の処理に移したので削除しました。日本生まれの立運年齢は修正前と1件も変わっていません（2万件で確認済み）。
- `Q2`（真太陽時の補正）の時刻計算を、ブラウザの地域設定や夏時間に左右されない UTC 計算に変更しました。
- `pro-adapter.js`：時刻不明の場合も、出生地の標準子午線を渡すように変更しました（節入りを出生国の時間で判定するため）。

## 変更していないが知っておいてほしい点（エンジンv142と共通）

1. **立運の計算方式**：「節入りまでの日数 ÷ 節と節の間の日数 × 10年」の比例方式です。一般的な「3日＝1年」と比べると、最大で2ヶ月ほど差が出ます。これが流派として意図したものか、ご確認ください。
2. **年運の切り替え**：暦の1月1日で切り替えています。1月1日〜立春前は、厳密には前の年の干支です（エンジンも同じ）。
3. **日本のサマータイム（1948〜1951年）**は補正していません（エンジンも同じ）。この期間に生まれた人は時柱が1時間ずれることがあります。
4. **韓国生まれ（1954〜1961年）**：当時の標準子午線127.5°は反映していません（出生地リストで135°固定）。
5. **大運は8本（立運＋80年）まで**しか計算していません。それより年上の人は、最後の大運が「今」として表示され続けます。
6. **節木運**は、月柱から第一大運に切り替わるところを節目として数えていません（エンジンのsetsuboku.jsと同じ扱い）。数えるべき流派であれば、追加で対応できます。

## 他サービス（四柱推命PRO v142）への注意
- ②の節入り時刻の不具合は、`app-pro.html` のエンジンにもそのまま残っています。同じ修正（`BJ2`＋年柱・月柱・ChildLimit を換算した時刻で判定）が必要です。
- エンジンv142では、立運前の人について `gogyoNow` / `kuuboNow` / `tsGroupNow` / `gogyoTaika` / `compatBrief` / 夫婦の冲判定などが `daeunIndex<0 → 0`、つまり**第1大運**を「今の大運」として扱っています。「0歳〜は月柱」のルールに合わせるなら、ここは月柱（`monthDu`）を使うのが正しい形です（主に子どもの命式に影響します）。
