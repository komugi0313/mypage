# 毎朝の配信メール：仕組みと、見本（mail-sample.html）と違って見える理由

対象：配信基盤を実装中のエンジニア
前提：2026-09-24 6:00 に実際に届いたメール（件名「【9/24(木)】りえさんの今日の運勢🌤」）と、引き継ぎ資料一式（`unkiyoho` 単体版 zip）を突き合わせて整理したもの。

---

## 1. 結論（3行）

1. **実装が間違っているのではなく、引き継ぎ資料の中に「正」が2つあり、食い違っていた。**
   - 本文の中身 → 「`my-tenki-demo.html` の `run()` と完全に同一」（仕様書 §10.2）
   - 見た目 → 「目標は `mail-sample.html`」（仕様書 §10.2・引き継ぎ §3-3）
   - この2ファイルは**セクション構成が違う**。実装は前者（`run()`）に忠実に作られている。
2. **メールとしてそのまま使えるテンプレートを渡していなかった。** `mail-sample.html` は Webページ（JS・背景画像・グラデーション・影で見た目を作っている）で、メールではそのまま動かない。そのため見た目はエンジニア側でゼロから組むことになった。
3. **件名も資料が2通りあった。** 仕様書の件名例「【7/9(木)】あかりさんの今日の運勢🌤」と、エンジンが返す `subject`（毎日変わる）。実装は前者を使っている。

→ 対応：**「メールの正」を `mail-sample.html` に一本化し、各セクションに入れる `generateDaily()` のフィールドを下の §4 の対応表で確定させる。**

---

## 2. 仕組み（データの流れ）

```
[会員データ]  生年月日・時刻・性別・ニックネーム・今の状況(rel)・関心(interests)
      │
      ▼
generateDaily(birth, dateJST, {nick, rel, sex, hour, minute, timeUnknown, personBazi, interests})
  （daily-engine.js / engine.js / bazi.js。DOM非依存の純JS。HTMLは作らない）
      │  返り値＝「差し込み用の値」だけ（subject, relIntro, weather, index, grade, theme,
      │  todayOne, love, loveMove, en, place, fortunes{friend,work,money,health,study},
      │  lucky{...}, koyomi.items, moon, kou, season, juni, focus, habit, onepoint, closeWord …）
      ▼
[メールテンプレート]  ← ここが「見た目」と「どのセクションを出すか」を決める層
      │  テーブルレイアウト＋インラインCSS（Gmail等は <style>・grid・背景画像・JS を削る／動かさない）
      ▼
送信（SES/SendGrid/Resend）→ mail_log 記録
```

ポイント：**エンジンは「文章の部品」を返すだけ**。どの部品をどの順番・どの見出しで・どんな装飾で並べるかはテンプレート層の仕事。今回の違いはすべてこのテンプレート層で起きている（エンジンの計算は正しく動いている）。

---

## 3. 届いたメールと見本の違い：原因の特定

届いたメールの文言を、引き継ぎファイルと照合した結果：

| 届いたメールの要素 | 出どころ | 見本 `mail-sample.html` にあるか |
|---|---|---|
| 紺色ヘッダー「MY DAILY FORECAST／私だけの運気予報」 | `my-tenki-demo.html`・サイト共通ヘッダー | ない（季節の便箋＋絵文字リボン） |
| 「ゆっくり起きて、今日もいい一日に。」 | エンジン `MORNING`（朝のひとこと） | ある（「今日も“いい縁日和”に…」の枠） |
| 「夫婦・家庭の縁」「家庭の時間のヒント」 | **`my-tenki-demo.html` の `run()` のみ**（rel=married 用の見出し） | ない（見本は「気になる人がいる」人向けの固定文） |
| 🌫️整える日／⚠️ゆらぎ注意日 | エンジン `koyomi.items` | ある（「今日のこよみメモ」として下の方） |
| 締め「元気と笑顔があふれますように。」 | エンジン `closeWord` | ある |
| 件名「【9/24(木)】りえさんの今日の運勢🌤」 | 仕様書 §10.2 の**件名例** | 見本側の正は `generateDaily().subject`（例「りえさん、今日の運気予報🌈｜今日は『晴れ時々くもり』」） |

### 3-1. 見た目が違う理由
- `mail-sample.html` の見た目の大半は **メールでは再現できない手段**で作られている：
  - 月替わりの季節テーマ（色・絵文字リボン・周りの飾り）は **JavaScript（`applyTheme()`）で切り替え** → メールではJSは動かない。
  - 背景画像（8月の花火など）、グラデーション、影、`::before/::after` の丸い飾り、`backdrop-filter`、grid → Gmail が削る／非対応。
- 引き継ぎ資料は「テーブル＋インラインCSSへ移植」「Web用CSSなので**構造の参考に**」としか書いておらず、**移植済みのテンプレートは渡していない**。
  → エンジニア側で、手元にある一番まとまったデザイン（`my-tenki-demo.html` の紺ヘッダー）を土台に組んだ、というのが自然な経緯。

### 3-2. 内容（セクション）が違う理由
- 仕様書 §10.2「生成ロジック＝`my-tenki-demo.html` の `run()` が組み立てる本文と**完全に同一**」に従うと、`run()` の見出し構成になる。`run()` は **会員の「今の状況(rel)」で見出しを差し替える**：

  | rel | 縁の見出し | 場所の見出し |
  |---|---|---|
  | single | 運命の人との距離 | 良い縁に出会いやすい場所 |
  | crush | 気になる人との距離 | 縁が動きやすい場所 |
  | partner | ふたりの縁 | ふたりの時間のヒント |
  | married | **夫婦・家庭の縁** | **家庭の時間のヒント** |
  | work | （恋愛の項目は出さず、仕事→対人→金運の順） | 縁が活きる場所 |

  りえさんのメールに「夫婦・家庭の縁」が出ているのは、登録が「結婚している」だったためと思われる（**仕様どおりの出し分け**）。
- 一方 `mail-sample.html` を**パラメータなしで開くと「あかりさん・気になる人がいる」前提の固定の見本文**が表示される。オーナーが思い描いていたのはこの見本文なので、「内容が想像と全然違う」と感じる。
- さらに、`mail-sample.html` にはあるが `run()` にはない（＝届いたメールに出ていない）セクションがある：
  - 🌙 今日の月（月齢）／🍃 七十二候 … `moon` / `kou`
  - 🔮 今日のあなたの鑑定（恋チャンスUP等のチップ＋開運アクション＋ラッキーカラー）… `lucky.action` / `lucky.color` / `koyomi` 等
  - 🎯 今日の注目テーマ（登録した関心に合わせる）… `focus`
  - 🔄 今日の運気の巡り … `juni.text`
  - 📚 今日の学び … `fortunes.study`
  - 「恋愛・ご縁」「仕事・チャレンジ」…のジャンル区切り見出し
  - 月替わりの季節の便箋

  **エンジンはこれらの値をすべて返している**（`mail-sample.html` の下部スクリプトが実際に使っている）。テンプレートで使っていないだけ。

### 3-3. 件名が違う理由
- 仕様書 §10.2 に件名**例**「【7/9(木)】あかりさんの今日の運勢🌤」がある。
- バックエンド仕様書 §4-4 では「件名＝`generateDaily().subject`」。エンジンは「呼びかけ＋その日のデータ」を組み合わせ、毎日違う件名（ほぼ1年被らない）を返す。
- 実装は前者を採用。**どちらにするかはオーナー判断**（下記 §5）。

## 4. メールの正（一本化案）：`mail-sample.html` の並び × フィールド対応表

`mail-sample.html` の上から順に、使うフィールドを示す（`?y=…&m=…&d=…&date=…&rel=…&sex=…&nick=…` を付けて開くと、下部スクリプトが実データを差し込む＝このスクリプトがそのまま対応表の実装例）。

| # | セクション（見本の見出し） | フィールド |
|---|---|---|
| 1 | ヘッダー：ロゴ・日付・「◯◯さん、おはようございます」・朝のひとこと・導入文 | `date`, `user.nick`, `morning`, `relIntro` |
| 2 | 🌙 今日の月／🍃 七十二候 | `moon{emoji,name,age,text}`, `kou{sekki,third,name,yomi}` |
| 3 | 🔮 今日のあなたの鑑定（チップ・開運アクション・ラッキーカラー） | `lucky.action`, `lucky.color`, `lucky.hex`（チップは見本の出し方に合わせる） |
| 4 | 天気・運勢指数・グレード・天気の説明 | `weather{icon,name}`, `index`, `grade`, `weatherMsg` |
| 5 | ✅ 今日はこれだけ | `todayOne` |
| 6 | 🌱 開運習慣 | `habit` |
| 7 | 🎯 今日の注目テーマ（関心登録がある人のみ） | `focus{emoji,label,text}` |
| 8 | 🌅 今日のあなた | `theme{axis,mean,line,message}` |
| 9 | 🔄 今日の運気の巡り | `juni.text` |
| 10 | 【恋愛・ご縁】縁（見出しは rel で差し替え）／恋愛運／恋の一手／出会いやすい場所 | `en{tag,body}`, `love`, `loveMove`, `place{direction,nature,city}` |
| 11 | 【仕事・チャレンジ】仕事・勝負運 | `fortunes.work` |
| 12 | 【お金・金運】金運 | `fortunes.money` |

| 18 | 💡 今日のワンポイント | `onepoint` |

rel による見出し差し替え（§3-2 の表）は `run()` のものを使ってよい。**「セクションの並びと有無は `mail-sample.html`、rel ごとの見出し名は `run()`」** とすれば両資料が矛盾しない。

### 月替わりの便箋をメールで出す方法
- JSは使えないので、**送信時にサーバー側で月（JST）を見て色と絵文字を決めて埋め込む**。`mail-sample.html` の `THEMES` 定義（`frame1/frame2/soft/accent/ink/deco`）をそのまま流用できる。
- グラデーションや背景画像は Gmail で崩れやすいので、**単色背景（`frame1`）＋絵文字リボン（`deco`）＋差し色（`accent`）** に落とすのが安全。背景画像を使う月（8月花火など）は、画像を絶対URLで `background` 属性＋単色フォールバック。

## 5. オーナーに決めてもらうこと

1. **件名**：
   - A. 日付入り固定形「【9/24(木)】りえさんの今日の運勢🌤」（今の実装。受信箱で日付が分かりやすい）
   - B. エンジンの `subject`（毎日違う文面で開封されやすい）
   - C. 両方：「【9/24(木)】」＋ `subject`
2. **メールの正を `mail-sample.html` に一本化してよいか**（§4 の並び）。
3. **季節の便箋**を §4 の簡略版（単色＋絵文字）で出すか。

## 6. 資料側で直すべきところ（再発防止）

- 仕様書 §10.2「本文＝`run()` と完全に同一」→「**文章（各値）は `generateDaily()` の返り値そのもの。セクションの並び・有無は `mail-sample.html`**」に修正。
- 件名の記述を1つに統一。
- `mail-sample-free.html` は古い固定見本（エンジン非連動・全員無料なので「無料版」という区別もない）。誤解のもとなので削除するか「参考・旧版」と明記。
- 理想は、**メール用テンプレート（テーブル＋インラインCSS、`generateDaily()` の返り値を受け取ってHTMLを返す関数）をプロトタイプ側から渡す**こと。そうすれば「見本と違う」はもう起きない。
