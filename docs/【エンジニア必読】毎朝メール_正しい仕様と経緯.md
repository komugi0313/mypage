## 3. なぜこうなったか（原因）

**原因はすべて、こちらからお渡しした資料の側にあります。** 実装が資料に従わなかったのではなく、資料の中に「正しいもの」が複数あって、互いに食い違っていました。

### 原因1：「本文の正」と「見た目の正」が別のファイルで、中身が食い違っていた
- 仕様書 §10.2 には、2つのことが書かれていました。
  - 「本文は **`my-tenki-demo.html` の `run()`** が組み立てる本文と**完全に同一**」
  - 「見た目の目標は **`mail-sample.html`**」
- この2ファイルは、**並んでいる項目も見出しも違います。** `my-tenki-demo.html` はアプリ画面のデモで、今日の月・七十二候、鑑定、学び、ジャンル見出しなどがありません。
- エンジニアさんは「完全に同一」と強く書かれた前者に従ったため、**項目が足りず、並びもデモ画面と同じ**になりました。ヘッダーの紺色の帯「MY DAILY FORECAST」も、`my-tenki-demo.html` のデザインです。

### 原因2：メールでそのまま使えるひな形を渡していなかった
- `mail-sample.html` は**Webページ**です。JavaScriptで月の便箋を切り替え、グラデーション・影・グリッドで見た目を作っています。メールではJavaScriptが動かず、GmailはCSSの多くを削ります。
- 資料には「テーブルレイアウト＋インラインCSSへ移植」「Web用CSSなので**構造の参考に**」としか書いておらず、**移植済みのひな形はありませんでした。**
- そのため、エンジニアさんが見た目をゼロから組むことになり、見本と違うデザインになりました。

### 原因3：件名の書き方が2通りあった
- 仕様書 §10.2 の件名例：`【7/9(木)】あかりさんの今日の運勢🌤`
- バックエンド仕様書 §4-4：件名＝`generateDaily().subject`
- 実装は前者を使っていました。**オーナー決定で「両方を組み合わせる」形に確定しました**（§1）。

### 原因4：季節の背景の設定が、見本ファイルごとにバラバラだった
- `mail-sample.html`：写真は **1・2・3・8月の4か月だけ**。ほかの月は色と絵文字だけ。
- `mail-sample-free.html` と `my-tenki-demo.html`：**12か月すべて写真**（オーナーが用意した `bg-*.jpg`）。
- 同じ「見本」なのに設定が違っていました。**正しいのは「12か月すべて写真」です**（§1）。

### 原因5：「無料版」という名前の古い見本が混ざっていた
- `mail-sample-free.html` は「無料版」という名前ですが、**このサービスは全員無料で、有料版・無料版の区別はありません。**
- また、このファイルは**エンジンとつながっていない固定の見本文**です（9月でも7月の「大暑」が出る）。
- 名前が誤解を招くので、メールの参考にはしないでください。

### 原因6：フッターの記載が、オーナーの決定と違っていた
- 引き継ぎ資料には「法定フッター：事業者名・**住所**」と書かれていました。
- オーナー決定は「**住所は載せない。会社名とメールアドレスはリンク先のページ（`tokushoho.html`）に載せる**」です。メール本文には「運営：72k株式会社｜運営者情報」だけを小さく入れます。

## 5. 実装の手順

1. `mail-template/render-daily-mail.js` を、`daily-engine.js`・`engine.js`・`bazi.js` と同じ場所に置く。
2. **画像をサーバーに置く**（`https://unkiyoho.jp/` の下）：
   - `icon-crystal.png`
   - `bg-*.jpg`（12枚）
   - `mail-template/mail-bg/` の中身（24枚）→ `https://unkiyoho.jp/mail-bg/` に置く
3. 毎朝のバッチで、会員ごとに次を実行する：

```js
const D = require('./daily-engine.js');
const { PersonBazi } = require('./bazi.js');
const { renderDailyMail } = require('./render-daily-mail.js');

const r = D.generateDaily(
  { y, m, d },                     // 生年月日
  { y: Y, m: M, d: DD },           // 配信日（JST）
  {
    nick, rel, sex,                // rel = single / crush / partner / married / work
    hour, minute, timeUnknown,     // 生まれた時刻（未入力なら timeUnknown: true）
    interests,                     // 登録の「関心」をそのまま（下の注意参照）
    personBazi: PersonBazi         // ★必ず渡す
  }
);
const mail = renderDailyMail(r, {
  assetBase:      'https://unkiyoho.jp/',
  unsubscribeUrl: 'https://unkiyoho.jp/unsubscribe.html?token=' + token,  // 会員ごとの解除トークン
  mypageUrl:      'https://unkiyoho.jp/mypage.html',
  aishouUrl:      'https://166unmei.com/',
  operatorUrl:    'https://unkiyoho.jp/tokushoho.html',
});
// 件名 mail.subject ／ HTML mail.html ／ テキスト版 mail.text で送信
```

4. `mail-template/samples/` の見本と見比べて、同じになっていることを確認する。特に `sample-0924-rie` は、9/24 に実際に届いたメールと同じ会員・同じ日なので、テスト送信で1981/6/10・既婚・女性・時刻なし・9/24 を指定すれば、**件名・本文とも完全に同じ**になるはず。季節の背景は `mail-template/client-check/months-12.jpg`（12か月の一覧）と見比べる。

## 6. 間違えやすい点（必ず確認）

- **`interests`（関心）は、登録フォームの日本語の値をそのまま渡す。** 例：`['恋愛', '仕事・キャリア']`
  - 使える値：恋愛／結婚／友達づくり／仕事・キャリア／習い事・勉強／投資／お金・家計／健康・ウェルネス／ヨガ・ピラティス
  - 英語（`love` など）に変換して渡すと、エンジンが読み取れず「🎯今日の注目テーマ」が出ません。こちらの見本作成でも、一度この間違いをしました。
- **`personBazi: PersonBazi` を必ず渡す。** 渡さないと運勢のランクが運命カレンダーとずれます。
- **日付はJSTで渡す。** UTCだと干支が1日ずれます。
- **テンプレートの見た目を変えるときは、グラデーション（background-image）を文字の下に使わない。** ダークモードで「明るい背景に明るい文字」になり、読めなくなります。背景は単色で指定してください。
- **`my-tenki-demo.html` はアプリ画面のデモです。メールの見た目・並びの参考にしないでください。**
- エンジンの文章を書き換えたり、項目を足し引きしたりしない。変更が必要なときはオーナーに確認する。

## 9. 資料の運用ルール（同じ間違いを繰り返さないために）

今回の原因は「正しいとされる資料が複数あり、互いに食い違っていたこと」でした。今後は次のルールを守ります。

1. **毎朝メールの正は、この資料と `mail-template/` だけ。** 仕様書・引き継ぎ資料・見本HTMLにメールの記述があっても、この資料と違えばこの資料が正しい。
2. **変更は「この資料」と「`mail-template/`」を同時に直す。** 片方だけ直すと、また食い違いが生まれる。見本（`samples/`）も必ず作り直す。
3. **見本は必ずロジック（`generateDaily()`）で生成する。** 手で書いた固定の見本文は作らない（`mail-sample-free.html` の失敗の再発防止）。
4. **「完全に同一」「必ず」と書くときは、何と同一なのかを1つだけ書く。** 2つの資料を別々に「正」と呼ばない。
5. **本番に出す前に、§8 のチェックリストを全部確認する。** 特に `sample-0924-rie` との完全一致。
6. **資料に書いていないことを判断するときは、自己判断で決めずオーナーに確認する。**

わからない点があれば、自己判断で直さず、オーナーに確認してください。
