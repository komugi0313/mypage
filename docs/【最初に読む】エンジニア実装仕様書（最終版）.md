## 3. 毎朝のメール（送信バッチ）

### 3-1. 作り方（HTMLは自前で組まない）

```js
const D = require('./daily-engine.js');                 // engine.js・bazi.js と同じフォルダ
const { PersonBazi } = require('./bazi.js');
const { renderDailyMail } = require('./render-daily-mail.js');   // 同じフォルダに jp-holidays.js も置く

const r = D.generateDaily(
  { y, m, d },                      // 生年月日
  { y: Y, m: M, d: DD },            // 配信日（日本時間 JST）
  {
    nick,                           // ニックネーム（6文字まで）
    rel,                            // single / crush / partner / married / work
    sex,                            // 'f'（女性）/ 'm'（男性）※登録の「女性」「男性」を変換して渡す
    hour, minute, timeUnknown,      // 生まれた時刻（未入力なら timeUnknown: true）
    interests,                      // 登録の「関心」を日本語のまま（例：['恋愛','仕事・キャリア']）
    personBazi: PersonBazi          // 必ず渡す（渡さないとカレンダーとランクがずれる）
  }
);
const mail = renderDailyMail(r, {
  assetBase:      'https://unkiyoho.jp/',
  unsubscribeUrl: 'https://unkiyoho.jp/unsubscribe.html?token=' + token,   // 会員ごとの解除トークン
  mypageUrl:      'https://unkiyoho.jp/mypage.html',
  aishouUrl:      'https://166unmei.com/',
  operatorUrl:    'https://unkiyoho.jp/tokushoho.html',
  refCode:        member.ref_code,                                         // 会員の紹介コード（§5）
});
// 件名 mail.subject ／ HTML mail.html ／ テキスト版 mail.text（multipart/alternative の text/plain）
```

- **その朝の最新の会員データ**（性別・今の状況・ニックネーム）で作る。マイページで変更したら翌朝から反映される。
- `jp-holidays.js` を `render-daily-mail.js` と**同じフォルダ**に置く（無いと祝日が出ないだけで、エラーにはならない）。
- 画像は `https://unkiyoho.jp/mail-bg/` に置く（`banner-01〜12.gif`・`sr-166.jpg`・`sr-nicocale.jpg`・`sr-pocket.jpg`・`crystal-30.png`）。CDN 経由で、長めのキャッシュ（例：`Cache-Control: public, max-age=31536000, immutable`）。画像を差し替えるときはファイル名を変える。
- 毎朝 **6:00（JST）までに**届ける（§7-D）。

## 6. 守ること（変えてはいけないもの）

1. **ファイルを丸ごと上書きしない**（§1）。
2. **カレンダーの記号・絵文字は変えない・消さない**：ランクの 💮◎〇△ と分野マーク（🌈 運命の人の日／🌷 出会い・モテ運の日／🌸 恋が動く日／💖 魅力が輝く／💰 金運／💼 勝負運／🌐 対人運／📚 学び など）は、開運カレンダー・毎朝のメール・**ほかの商品（1.66相性診断など）と連動**している。変える必要があるときはオーナーが決め、**連動するすべての商品で同時に**変える。
3. **運勢の計算・エンジンの文章を勝手に書き換えない**。変えるときはオーナーに確認し、品質検査（§3-3）を PASS させる。
4. **メールのHTMLを自前で組まない**。`render-daily-mail.js` を使う。
5. **メールに写真の背景を戻さない**（1通が約500KBになり、30万人では毎月1TB以上の転送）。
6. メールの文字が乗る箱に**グラデーション（background-image）を使わない**（ダークモードで読めなくなる）。背景は単色（`background-color`＋`bgcolor`）。
7. 日付は**日本時間（JST）**で扱う（UTCだと干支が1日ずれる）。
8. `generateDaily()` には **`personBazi: PersonBazi` を必ず渡す**。関心（`interests`）は**日本語のまま**渡す（英語に変換すると「今日の注目テーマ」が出ない）。
9. **運営者情報（`tokushoho.html`）に住所（所在地）を載せない**（オーナー決定：無料のサービスのため）。載せるのは事業者名とお問い合わせ先（info@72k.ai）。※ 有料の Pocket鑑定は、Pocket鑑定のサイト側の表記に従う。

## 7. 毎朝30万通を届けるための「送信の立ち上げと監視」

Gmail・Yahoo は、1日5,000通以上送る送信者に次を**必須**にしています（会員1万人で対象になります）。

**A. 送る前にそろえるもの（必須）**
- 送信元ドメインの **SPF・DKIM・DMARC**（DMARC は `p=none` から始め、レポートを見て `quarantine` へ）。From と DKIM のドメインをそろえる。
- ワンクリック配信停止（§5-8）。
- **迷惑メール報告率 0.1％未満を目標、0.3％を絶対に超えない**。

**B. 立ち上げ（ウォームアップ）**
- いきなり数万通を送らない。最初の2〜4週間は、1日の送信数を少しずつ増やす（目安：前日の1.5〜2倍まで）。SNS などで登録が一気に増えた日は、新しい会員への送信を数日に分ける。

**C. 毎日見る数字**

| 数字 | 見る場所 | 目安・対応 |
|---|---|---|
| 迷惑メール報告率 | Google Postmaster Tools／送信サービスの苦情通知 | 0.1％を超えたら原因を調べる。0.3％に近づいたら送信を減らす |
| ドメイン・IPの評判 | Google Postmaster Tools | 「低い」「悪い」になったら送信を減らして原因を調べる |
| 不達（バウンス） | 送信サービス | ハードバウンスは即、配信停止。ソフトバウンスは3回続いたら停止。2％超えは要注意 |
| 苦情（迷惑メール報告）した人 | 送信サービス | 即、配信停止 |

- 長く読まれていない会員（例：90日クリックなし）には「このまま受け取りますか？」を1回送り、反応がなければ配信を止める。
- 携帯キャリアのメール（docomo・au・SoftBank）向けに、登録完了画面で「`@unkiyoho.jp` からのメールを受け取れるように設定してください」と案内するとよい。

**D. 30万通を6時までに届ける**
- 文面づくりは1通あたり約4ミリ秒（実測）。30万通で1台約22分なので、3時ごろから作っておく。
- 送信は4時30分ごろに始め、90分で送り切る＝毎秒約60通。送信サービスの上限（1日・1秒あたり）を事前に引き上げておく。
- 途中で失敗しても二重に送らないよう、「送信済み」を記録してから次へ進む。
