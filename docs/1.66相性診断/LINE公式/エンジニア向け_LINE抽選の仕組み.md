# エンジニア向け：LINE公式「オンライン鑑定プレゼント」の応募受付と抽選の仕組み

## 0. 決まっていること（オーナー決定 10/12）
- 毎月2名に、オンライン鑑定をプレゼントする。
- 応募期間：毎月1日 0:00 〜 その月の最終日 23:59:59（日本時間・JST）。
- 応募方法：本アカウント（1.66 奇跡の相性診断）のトークに「応募」と送る。
- 当選の連絡：翌月10日までに、本アカウントのトークで送る。
- 1つのLINEアカウントにつき、1か月1回まで（何度送っても1回）。
- 応募の時点では **LINEの userId だけを記録する**。生年月日・名前などは、当選者にだけ聞く。
- 規約：`抽選の応募規約.md`（サイトのページ https://166unmei.com/campaign.html ＝ 1.66 の `campaign.html`）。文面：`LINE公式に入れる内容.md` の「抽選のオンライン鑑定」。
- 想定：月に20万件の応募が来ても止まらないこと。

## 1. 用意するもの
1. LINE Developers で、本アカウントにつながった **Messaging API チャネル** を作る（LINE公式アカウントの管理画面から Messaging API を有効にする）。
   - 控えるもの：チャネルシークレット、チャネルアクセストークン（長期）。サーバーの環境変数に置き、ソースや資料に書かない。
2. サーバーに **Webhook の受け口**（HTTPS、例：`POST /line/webhook`）を作り、LINE Developers に登録して「Webhookの利用」をオンにする。
3. LINE公式アカウントの管理画面の「応答設定」
   - Webhook：オン
   - あいさつメッセージ：オン（文面は `LINE公式に入れる内容.md`）
   - 応答メッセージ（キーワード「応募」）：**オフ**（受付の返事は Webhook から返す。両方オンだと返事が2回届く）
   - チャット：使う場合はオン（オーナーが当選者とやりとりするため）

## 2. Webhook でやること
1. **署名の確認**：ヘッダー `x-line-signature` を、チャネルシークレットで計算した HMAC-SHA256（Base64）と比べる。合わなければ 401 で捨てる。
2. **すぐに 200 を返す**：重い処理は後ろの仕事（キュー）に回す。LINE は返事が遅いと同じイベントを送り直してくる。
3. **二重処理を防ぐ**：`webhookEventId` を保存し、同じものが来たら何もしない（送り直し対策）。
4. **「応募」の判定**：`type=message` かつ `message.type=text` で、文字を整えてから判定する。
   - 前後の空白・全角空白・改行・句読点・絵文字を取りのぞく。
   - 「応募」「おうぼ」「オウボ」「応募します」「応募する」を応募とみなす。
   - それ以外の文は何もしない（チャットでオーナーが読む）。
5. **記録**：その時点の JST の年月（例 `2026-11`）で、`entries` に1行入れる（下の表）。すでにあれば入れない。
6. **返事（reply API。通数に数えられない）**
   - 初めての応募：`LINE公式に入れる内容.md` の「応募と送られたときの自動の返事」
   - 同じ月に2回目以降：「今月はすでに受け付けています。当選された方には、翌月10日までにこのトークでご連絡します。」
7. **follow／unfollow**（友だち追加・ブロック）：`users` の状態を更新するだけ（抽選のときにブロック中の人を外すため）。

## 3. 表（データベース）
```
entries(
  month        CHAR(7)   -- 'YYYY-MM'（JST）
  user_id      VARCHAR   -- LINE の userId（U から始まる文字列）
  created_at   TIMESTAMP -- 受け付けた時刻（UTCで保存、表示はJST）
  PRIMARY KEY (month, user_id)
)
users(
  user_id      VARCHAR PRIMARY KEY
  blocked      BOOLEAN   -- unfollow で true、follow で false
  updated_at   TIMESTAMP
)
draws(
  month        CHAR(7) PRIMARY KEY
  entry_count  INT       -- 抽選した時点の応募数
  entries_hash CHAR(64)  -- 応募者一覧（user_id を並べ替えて改行でつないだもの）の SHA-256
  drawn_at     TIMESTAMP
  method       TEXT      -- 'crypto random, 2 winners'
)
winners(
  month        CHAR(7)
  user_id      VARCHAR
  rank         INT       -- 1,2（くり上げで3以降）
  status       VARCHAR   -- 'notified' / 'replied' / 'scheduled' / 'done' / 'cancelled'
  notified_at  TIMESTAMP
  PRIMARY KEY (month, user_id)
)
webhook_events(event_id VARCHAR PRIMARY KEY, received_at TIMESTAMP)  -- 30日で消す
```
- **生年月日・名前・希望日時はこの表に入れない。** 当選者とのやりとりは、オーナーが LINE公式の管理画面のチャットで行う。
- 20万件/月でも、1行は数十バイト。`(month, user_id)` の主キーで重複は自然に防げる。

## 4. 抽選（毎月1日 0:10 JST に自動で実行）
1. 前の月（例：12月1日なら `2026-11`）の `entries` から、`users.blocked = true` の人をのぞいた一覧を作る。
2. `draws` に応募数と一覧のハッシュを保存する（あとで「公平に選んだ」と示すため）。
3. **暗号用の乱数**（Node.js なら `crypto.randomInt`、Python なら `secrets`）で、重ならないように2名を選ぶ。`Math.random()` は使わない。
4. `winners` に rank 1・2 として保存する。
5. 同じ月をもう一度抽選できないようにする（`draws.month` が主キー）。

## 5. 当選者への連絡（毎月1日〜10日）
- push API で、当選者2名に `LINE公式に入れる内容.md` の「当選した人に送る文」を送る（2通。通数に数える）。
- 自動で送らず、オーナーが管理画面で確認してから送るボタンでもよい（オーナーと相談）。
- 送れなかったとき（ブロックなど）は `status=cancelled` にして、くり上げで1名を選び直す（4-3 と同じやり方、rank 3）。
- 当選の連絡から7日たってもお返事がない人は、オーナーの判断で `cancelled` にして、くり上げ抽選をする。

## 6. 個人情報と消す時期（規約 9 と同じ）
- `entries` は、その月の抽選と当選の手続きが終わったあと［3か月］以内に消す（`draws` の件数とハッシュは残してよい）。
- `webhook_events` は30日で消す。
- 当選者の生年月日などは LINE のチャットにだけあるので、鑑定を行ってから［3か月］以内に、オーナーがチャットの履歴を消す。
- ログに userId 以外の個人情報（メッセージ本文など）を書かない。

## 7. 20万件/月に耐えるために
- Webhook はすぐ 200 を返し、DB への書き込みはキューで行う。
- 1日に応募が集中しても（例：月初の1日に5万件）、秒あたり数十件。小さなサーバーでも足りるが、Webhook の受け口は落ちないように2台以上か、自動で増える仕組みにする。
- reply API の通数は数えられないので、20万件の受付の返事に費用はかからない。push は当選者だけなので、月に数通。
- **友だち全員への一斉配信（お知らせ）は通数に数える**。20万人の友だちに月1回送ると、スタンダードプランと追加の通数が必要（LINEヤフー for Business の料金ページで最新の金額を確認）。

## 8. 確かめること（テスト）
- 「応募」「 応募 」「応募します」「おうぼ」で受け付けられ、「おうぼー！」のような関係ない文や画像では受け付けない。
- 同じ月に2回送ると2回目は「すでに受け付けています」になり、表は1行のまま。
- 月末 23:59:59 と翌月 0:00:00（JST）の境目で、正しい月に入る。
- 同じ Webhook が2回届いても、表は1行・返事は1回。
- 署名がちがうリクエストは 401。
- ブロック中の人は抽選されない。
- 抽選をもう一度実行しても、当選者が変わらない（2回目ははじかれる）。
- 1万件・20万件のテストデータで、抽選が数秒で終わる。

## 9. 1.66 のサイト・開運予報への影響
- この仕組みは LINE公式アカウントの中だけで動く。1.66 のサイト・開運予報のメールには手を入れない。
- サイトのプライバシーポリシーに「LINE公式アカウントでのキャンペーン」の項目を足すかどうかは、オーナーと相談（案は別に用意できる）。
