# 運勢ロジック と 毎朝メール配信の考え方（エンジニア向け）

- 対象：「私だけの運気予報」（unkiyoho.jp）の毎朝メール配信を実装・運用するエンジニア
- 位置づけ：`仕様書_エンジニア向け_相性診断と運気予報.md`（§6・§10・§11）の補足。ロジックの正本コードは `engine.js` / `bazi.js` / `daily-engine.js`。
- 最重要の結論：**毎朝の配信は「固定のNパターン」ではなく、会員1人ずつ生成して1通ずつ送る**（＝会員数ぶん）。

---

## 0. いちばん多い質問への回答

> **Q. 毎日“何パターン”のメールを送ればいい？ 500人いても60干支ぶんの60通では？**

**A. パターン数ではありません。毎朝「配信ONの会員数ぶん」を、1人につき1通ずつ生成して送ります。**
500人なら500通、1,000人なら1,000通。あらかじめ数パターンを作って割り当てる方式ではなく、**会員ごとにその人の生年月日から本文を計算して生成**します（パーソナライズド配信）。

理由は§2の「骨格」と「文面」の切り分けにあります。占いの骨格（指数・天気・グレード・縁・五行）は四柱推命的に60干支ベースで共通になりますが、**文面（実際の文章）は生年月日をシードに混ぜて個別化**しているため、テンプレ割り当てでは全員同じ文章になってしまいます。→ **会員ごとに生成**してください。

---

## 1. 全体像

```
1日の1人分の出力 = 【骨格】you × today （＋喜忌）  +  【文面】個人シード × 独立プール
  you   = 本人の日柱（生年月日→干支：60通り）
  today = その日の干支（60日周期・全員共通）
  喜忌  = 命式(生年月日＋時刻＋性別)から求める喜神/忌神
  個人シード = その日 + 生年月日ハッシュ（＝同一干支の別人でも文面が分散）
```

- 計算は**決定論**（乱数なし）。同じ入力なら必ず同じ結果＝**メール・マイページのカレンダー・体験デモが完全一致**（仕様書§11の「必須契約」）。
- 判定は**JST固定**（UTCで「今日」を出すと干支が1日ズレる）。

---

## 2. 「骨格」と「文面」の切り分け（ここが核心）

### 2-1. 骨格（占いの中身）＝ ほぼ60干支ベース（四柱推命的に正しい）
指数・天気・グレード(💮◎〇△)・縁レベル(🌈)・神殺・注目五行は、**`you（本人の日柱）× today（その日の干支）`** だけで決まる（`daily-engine.js`：`dailyGrade` / `weather` / `enToday` / `koyomiOf`）。
→ **同じ日柱（干支）の人は骨格が同じ**。これは「同じ命式なら同じ日運になるべき」という四柱推命として正しい挙動。
- 厳密には **60干支 ×（命式の喜神/忌神）**。喜忌は生年月日＋時刻から求める（`PersonBazi`）ので、同じ日柱でもグレードがズレることがある（`dayRawScore` の ±1.2、閾値、`ymAdjust`）。

### 2-2. 文面（実際の文章）＝ 生年月日で分散（60ではない）
文面は「その日 + 生年月日ハッシュ」の個人シードで各プールから選ぶ（`generateDaily` 内、既定 `opts.spread=true`）。
```js
var spread = (opts.spread !== false);                    // 既定ON
var pseed  = spread ? (seed + hash(生年月日)) : (seed + 日柱ベース);
var ubase  = pseed - seed;                               // 文面はこの個人シードでプール選択
```
コード原文コメント：「生年月日を混ぜ、**同一日柱の別人でも文面が分散**する（四柱推命の“骨格”＝指数/天気/テーマ/縁レベル/五行 は you×today で不変のまま。変わるのは文言だけ＝正確性を保ったまま重複回避）」
→ **500人なら文面は最大500通りに散り、“60通りの同じメール”にはならない**。`opts.spread=false` にすると文面も日柱ベース（同一干支＝同一文面）に戻せる（既定は分散ON）。

## 3. 「何パターンか」を層で答えると

| 層 | 何で決まる | 種類数（1日あたり） |
|---|---|---|
| グレード表示 | 本人分布からの相対評価 | **4段階**（💮特別な日／◎調子のいい日／〇普通の日／△無理しない日） |
| 天気アイコン | グレード由来の指数 idx | **5段階**（☀️縁・快晴／🌤️縁・晴れ／⛅晴れ時々くもり／☁️くもり／🌦️にわか雨のち晴れ） |
| 縁マーク | `you × today` | **3レベル**（🌈運命の人の日／恋が動く日／準備の日） |
| こよみ・神殺 | `you × today`（🌀は命式必要） | **5種**の該当有無（🌫️空亡／🍀貴人／🐴駅馬／⚠️沖／🌀年月柱冲）＝部分集合の組合せ |
| 骨格（総合） | `you × today ×喜忌` | **≒60干支 ×喜忌の型** |
| 文面（文章） | 個人シード×独立プール | **会員数ぶんに分散**（同一干支でも重複しない設計） |

参考プール規模の例：冒頭あいさつ4種／恋愛汎用6種/十神／**恋の一手 20×19＝380通り（≈1年重複なし）**（`LM_SITU`×`LM_EFFECT`）／恋の動き約22種 ほか多数を掛け合わせ。実測（仕様書§11）：同一人物120日連続で完全一致0件・前日一致0/12。

### グレード判定の式（`dailyGrade` / `dayRawScore`）
```
素点 = GRADE_BASE[十神] + 喜神(+1.2)/忌神(−1.2) + 沖(−2.0) + ymAdjust(流年流月 ×YM_SCALE=0.6)
閾値 = 本人の60干支スコア分布から  ◎=上位約28%(72%ile) / △=下位約15%
判定順：🌈→💮 / 桃花×高得点×非沖→💮 / 上位28%→◎ / 恋の合図×非沖×中位以上→◎ / 下位15%→△ / それ以外→〇
```
（`GRADE_BASE`：正官2, 正財1.8, 偏財1.6, 食神1.4, 印綬1.0, 比肩0.6, 偏印0.2, 傷官−0.8, 劫財−1.0, 偏官−2.0）

## 4. 毎朝バッチ（実装の要点・仕様書§10.2/§14）

```
毎朝 JST 6:00 までに：
  users を全件ループ（mail_opt=ON かつ 未オプトアウトのみ）
    → generateDaily(birth, {
         rel, sex, nick,
         hour, minute, timeUnknown,   // 登録の birthTime を必ず反映（未入力は timeUnknown=true）
         personBazi                    // ★必ず渡す（PersonBazi と同一バージョンの bazi.js/engine.js）
       })
    → 返り値（todayOne＝今日の1アクション、koyomi.items＝こよみマーク 等）から
       HTMLメール（テーブルレイアウト＋インラインCSS）を組み立て（見た目の目標＝ mail-sample.html）
    → SES 等で本人宛に送信
    → mail_log に記録（date, channel, status）
```

- **`generateDaily` は DOM非依存の純JS**。Node で `require('./daily-engine.js')`（`engine.js` を自動 require、`bazi.js` は同ディレクトリに置く）してそのまま流用。移植・書き直し不要。
- **`personBazi` を渡し忘れない**：渡さないと喜忌が空（中庸扱い）になり、`favSet`/忌神/`ymAdjust`/素点がズレて「メール〇／カレンダー◎」の不一致が出る（仕様書§11-1）。
- **JST基準**で「今日」を判定（配信もJSTで揃える）。
- **法定フッター**：機能する配信停止URL（§配信停止）／設定変更（マイページ）リンク／事業者名・住所。
- 性能：1通の生成はミリ秒級。500人でも数秒。規模が増えても「ループして送るだけ」（キュー/並列は送信基盤側の話）。追加のAI/API課金は不要。
- 決定論なので **前夜に会員ぶん先生成→朝に送信** という運用も可（結果はカレンダー/デモと一致）。

---

## 5. 禁止・不変（仕様書§0・§13）

- ❌ `bazi.js` / `engine.js` / `daily-engine.js` の **計算・定数・シード・プール長** の改変（暦周期と互いに素に設計。変えると全画面の結果がズレる）。
- ❌ グレード定数・判定順・`YM_SCALE=0.6` の変更。
- ❌ 毎朝メールを別ロジック/別バージョンのエンジンで生成すること（カレンダーとズレる）。
- ❌ UTCで「今日」を判定すること（JST固定）。

## 6. エンジニアへの一言まとめ

**「毎日のメールは“Nパターン”ではなく、配信ONの会員数ぶんを1人1通ずつ生成して送る。生成は `generateDaily(birth, {…, personBazi})` を会員ごとに呼ぶだけ。占いの骨格は干支ベースで共通だが、文面は生年月日で個別化されるので、テンプレ割り当てにはしない。」**
