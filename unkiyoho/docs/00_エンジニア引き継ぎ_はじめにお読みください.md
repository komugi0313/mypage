## 3. ★メール配信の仕組み（本書の主題）

### 3-1. 送るのは「固定パターン」ではなく **会員1人につき1通**
- 会員が500人なら**500通**。あらかじめNパターンを作って配るのではなく、**会員ごとにその人の生年月日から本文を計算して生成**します（パーソナライズド配信）。
- 占いの“骨格”（指数・天気・グレード・縁・五行）は四柱推命で干支ベースになりますが、**文面は生年月日で個別化**されるため、テンプレ割り当てにはしません。→ **必ず会員ごとに生成**。
- 詳細と根拠：`運勢ロジックと配信_エンジニア向け.md`／`文言プール監査_エンジニア向け.md`。

### 3-2. 毎朝バッチの流れ（JST 6:00 までに全会員へ）
```
毎朝 JST 6:00 までに：
  users を全件ループ（mail_opt=ON かつ 未オプトアウトのみ）
    → generateDaily(birth, {
         rel, sex, nick,
         hour, minute, timeUnknown,   // 登録の birthTime を反映（未入力は timeUnknown=true）
         personBazi                    // ★必ず渡す（PersonBazi と同一バージョンの bazi.js/engine.js）
       })
    → 返り値のスロット（relIntro＝冒頭あいさつ、todayOne＝今日の1アクション、
       koyomi.items＝こよみマーク、天気・指数・各運 …）から
       HTMLメールを組み立て（★テーブルレイアウト＋インラインCSS。見た目の目標＝ mail-sample.html）
    → 送信サービス（SES/SendGrid/Resend 等）で本人宛に送信
    → mail_log に記録（date, channel, status）
```
- **`generateDaily` は DOM非依存の純JS**。Node で `require('./daily-engine.js')`（`engine.js` を自動 require、`bazi.js` を同ディレクトリに置く）してそのまま使える。移植・書き直し不要。
- **`personBazi` を渡し忘れない**：渡さないと喜神/忌神が空（中庸扱い）になり、グレードがカレンダーとズレる（メール＝カレンダー一致が崩れる）。
- **JST 固定**（UTCで「今日」を出すと干支が1日ズレる）。
- 1通の生成はミリ秒級。500人でも数秒。規模が増えても「ループして送るだけ」。追加のAI/API課金は不要。
- 決定論なので**前夜に会員ぶん先に生成→朝に送信**でも可（結果は画面のカレンダー・デモと必ず一致＝§11の必須契約）。

### 3-3. HTMLメール化の注意
- 見本 `mail-sample.html` / `mail-sample-free.html` は Web用CSS（grid等）。実配信は **Gmail等がCSSを削る**ため、**テーブルレイアウト＋インラインCSS**へ移植する。
- **法定フッター（特定電子メール法・必須）**：機能する**配信停止URL**（§5）／設定変更（マイページ）リンク／事業者名・住所。
- 末尾に「1.66相性診断への導線＋シェアボタン」ブロック（見本の該当ブロックが正）。`example.com` を本番URLへ。

## 4. ログイン（認証）の仕組み ── 要約

- 方式：**パスワードレス（メール確認コード / OTP）**。パスワードは扱わない。
- 動線：登録直後は「登録→確認コード→そのままマイページ」、後日は「メール入力→確認コード→マイページ」。施錠は**マイページのみ**（LP・相性診断・体験デモは公開）。
- API（4本）：`/auth/request-code`・`/auth/verify-code`・`/auth/logout`・`/auth/session`。
- 「ずっとログイン」ON（既定）＝ログアウトするまで維持（長期Cookie＋利用のたびに期限延長）。OFF＝共用端末向けに短命。
- **セキュリティの要**：`auth.js` の localStorage セッションは**画面の出し分け(UX)専用**。会員データを返すAPIは**必ずサーバーで Cookie セッションを検証**してから返す（クライアント判定を信用しない）。
- 詳細（入出力・エラーコード・データモデル・本人確認）：**`認証設計_引き継ぎ.md`**。

## 5. 配信停止（ログイン不要・法令必須）

- 毎朝メールの「配信停止」リンクは、**受信者ごとの解除トークン付きURL**（例：`unsubscribe.html?token=XXXX`）にする。**ログイン不要・ワンクリックで確実に停止**（特定電子メール法）。
- 同梱ページ `unsubscribe.html` が入口。本番は `token` を `/mail/unsubscribe`・`/mail/resubscribe` へ送る（詳細：`認証設計_引き継ぎ.md` §4-6）。
- マイページの「毎朝の予報メール」トグル（`#swMail`）も同じ `mail_opt` を読み書き（フロントは `unkiyoho_mail_opt` で連動済み）。

## 6. データモデル（推奨最小）

```
users:   id, email(uniq), nick, birth_date, birth_time(null可), time_unknown(bool),
         sex, pref, rel, interests(json), mail_opt(bool),
         minor_consent(bool), consent_at(datetime), created_at, updated_at
otp:     email, code_hash(平文保存禁止), purpose, expires_at(10分), attempts(上限5), sent_at
sessions: token, user_id, expires_at, remember(bool)
mail_log: id, user_id, date, channel(email/line), status(sent/bounce/fail), sent_at
unsub_token: user_id, token   // ワンクリック配信停止用
```
- 会員データは **内部の user_id に紐づけ**、メールは1属性として扱う（メール変更してもデータを失わない）。
- 生年月日・時刻は要配慮に準じる個人情報。保存時暗号化・アクセス制御を厳格に。同意・解約の記録は消さない。
