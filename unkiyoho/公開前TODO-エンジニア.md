## ⑥ ログイン認証基盤（パスワードの扱い）

**現状**：`register.html` のパスワード項目は**非表示化済み**（メール収集モデルでは不要／平文収集を避けるため）。バリデーションも解除済み。マイページにログイン認証は無い（プロトタイプ）。

**方針**
- 当面のモデル（メール収集＋広告）では**ログインパスワードは不要**。マイページは登録情報の引き継ぎ（localStorage）で動作。
- 将来ログイン認証を導入する場合：
  - パスワードは**サーバー側でハッシュ化（bcrypt/argon2＋salt）**。Googleフォーム等に平文で送らない。
  - もしくはパスワードレス（メールマジックリンク／OTP）を推奨。
- 実装時に `register.html` のパスワード項目（コメントアウト済み）を復活させ、認証APIへ接続。

## ⑯-2 画像の軽量化（ビルド時／要ツール）

**現状**：画像合計 約10MB（png 2.9MB／jpg 2.0MB／webp 5.2MB＝マスコット60体3.7MB含む）。
- **マスコット（60体・webp）は必要時のみ読み込み**（診断結果で該当日だけ `.src` 設定）＝初回表示では読まれない。対応不要。
- **重いショーケースPNGに `loading="lazy"` を付与済み**（`pop-mail.png` / `pop-cal-detail.png` / `lp-detail.png`）＝初回のブロッキングは解消。

**やること（この環境にツールが無いためビルド/手元で）**：大きいPNGをWebPへ変換し、参照を差し替え。
| 現状 | 変換後(目安) | 用途 |
|---|---|---|
| lp-detail.png 690KB | 〜150KB | LPのマークの見かた図 |
| pop-mail.png 388KB | 〜90KB | トップのメール見本 |
| pop-cal-detail.png 374KB | 〜90KB | トップのカレンダー見本 |
| pop-cal-detail 等その他PNG | 合計で約2MB→0.7MBへ | |

- コマンド例：`cwebp -q 82 lp-detail.png -o lp-detail.webp`（または squoosh / sharp）。
- **OGP画像（ogp-tenki.png / ogp-1.66.png）はWebPにしない**（SNSスクレイパー互換のためPNG/JPGのまま）。
- 変換後、各HTMLの `src="....png"` を `.webp` に差し替え（`<picture>`でPNGフォールバックを付けるとより安全）。
- 期待効果：初回以降の総ダウンロードを約1.5〜2MB削減。
