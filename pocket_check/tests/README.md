# 自動テスト

```
npm test        # または node tests/run.js
```

決定的（ネットワーク不要・APIキー不要）で、実ファイルから検証します。3本立て：

**A. 構文** — index.html / lp.html / legal.html の全インラインJS、および functions/*・pkiap-adapter・sw.js が構文として通るか。

**B. i18n構造（10言語 ja/en/zh/zt/ko/vi/es/pt/id/th）**
- 翻訳漏れ：i18nオブジェクトが全10言語そろっているか（＝英語フォールバックが出ないか）
- 言語スロット取り違え：韓国語の枠にタイ語、など"支配的スクリプトの不一致"
- 文字化け（U+FFFD）
- 通貨整合：日本語プランは¥、他はUSD

**C. 振り分けロジック**（課金・安全・話題・誤読防止を決める判定関数を index.html から抽出して実行）
- `classifyRisk`：自傷は検知、死別/家族の話は危機扱いにしない
- `_effectiveTopic`：恋愛/仕事/金運/家族/結婚/自分の判定
- `_isBillableDeep`：本格鑑定＝課金、雑談/相づち/締め/理屈＝無料
- `_isAmbiguousInput`：断片入力は確認ターン（かつ絶対に課金しない）
- `_isCorrection`：AI鑑定の直後の訂正だけ無料対象

## 意図的な限界

これはAIの**会話品質そのもの**は測れない（それには実APIでの評価が要る）。
測るのは「どの発言をどう振り分けるか」という**決定的な土台**で、ここの回帰＝
課金ミス・安全誤判定・誤読を確実に捕まえる。会話品質のE2E評価を足すなら、
実際のGemini呼び出しを使う別ハーネスが必要（本スイートとは分離する）。

## 追加のしかた

`tests/run.js` の各配列（`risk` / `topic` / `billT` / `ambT`）にケースを足すだけ。
新しい判定関数を足したら、抽出リスト（`grabFn` を呼ぶ配列）に名前を追加する。
