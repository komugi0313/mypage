# 会話品質の実機評価（live eval）

実際の Gemini を、**アプリ本体のパイプライン（answer()）そのまま**で叩き、
最重要ルールを守れているかを自動採点する。tests/（決定的な単体）とは別物で、
こちらは**実APIを使う**（ネットワーク＋少額コストが発生）。

```
GEMINI_API_KEY=xxxx npm run eval              # 基本10シナリオ（言語順守/実在プローブ/グリーフ/確認ファースト/恐怖商法 ほか）
GEMINI_API_KEY=xxxx npm run eval:adversarial  # 崩れやすい6シナリオ（whose-words/年齢非表示/誤wrap/雑文/死の予言/締め）
```

## 仕組み

`eval/harness.js` が **DOM/ブラウザをスタブ**して、`pro-bazi.js`＋`pro-adapter.js`＋
index.html のメインスクリプトを Node の vm 上でそのまま実行する。これにより
本物の `computeChart()` と `buildSystemPrompt()`（実測 約118,000字）が動く。
`window.PK_DIRECT_KEY` に env のキーを差すと、`answer()` が体験モードとして
Gemini を直接呼ぶ＝**実際のユーザー体験と同じ経路**を評価できる。

## セキュリティ（重要）

- キーは **環境変数からのみ** 受け取る。**ファイルには絶対に書かない・コミットしない**。
- 評価に使ったキーは**使い終わったらローテーション（再発行）**すること。
- 本番のキーはサーバー側 env（`GEMINI_API_KEY`）で運用し、フロントには出さない。

## 限界（正直に）

- スコアは**その1回の実行**のもの（生成は非決定的。日で揺れる）。
- チェックは正規表現ベースで、**言語順守・禁止語・年齢/生年月日・締め**などは高信頼だが、
  「捏造していないか」「本当に的確か」といった意味理解は近似。過検知・見逃しがあり得る。
- カバレッジは代表シナリオのみ。多ターンの繰り返し回避や長期記憶の追従などは未カバー。
- あくまで「回帰していないかの実機スモーク＋高リスク項目の実証」であり、
  人手レビュー（各言語ネイティブの目視）の代わりにはならない。
