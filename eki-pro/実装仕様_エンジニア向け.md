**会員まわり（ログイン状態・使える状態・解約後の利用・圏外での利用・status の一覧）の正は、同梱の `実装仕様_会員まわり_共通.md`（PRO・ビギナーと同一）**。`status` は `active`／`trialing`／`canceling`／`canceled`／`past_due`／`unpaid`／`none`、`periodEnd` は `YYYY-MM-DD`。

**言葉づかいの方針（重要）**：このツールは「易経の正しい言葉を示し、それを現代語で解き明かす」もの（教科書）。アプリの画面・台本・要点・深掘り相談では、卦の名前・卦辞・爻辞の**原文を正確に**示し、必ず「現代語にすると〜」を添える（原文データ `HEXDB` は書きかえない）。**お客様にお渡しする鑑定書だけ**は専門用語なしの現代語（卦の名前・漢文を出さない。取りこぼしは `plainEki()` で置きかえ）。64卦の現代語の意味は `MODERN64`、古い言い回しが残る爻の言葉の現代語訳は `TAI_FIX`（いずれも `app/index.html`）。「専門用語：専門的に／噛み砕く」の切り替えは廃止（常に「原文＋現代語」）。

**鑑定書（お客様にお渡しする版）**：アプリの「鑑定書を作成」で、①ご相談への答え②いまの状況③これからの流れ（動いた爻・之卦）④生まれ持った性質⑤時期の目安（④⑤は「相談者の生年月日」があるときだけ。PRO版と同じ計算エンジンで今年から3年）⑥具体的なアドバイス⑦結びのことば、の構成で作る。オンライン時は `gemini` 中継で本文を生成（リクエストに **`x-eki-kind: sho`** ヘッダが付く＝1回の鑑定に付随する作成なので、**無料期間の1日3回の回数には数えない**こと）。オフライン・失敗時は内蔵データの定型文で同じ構成。鑑定士用の「要点」・裏卦（互卦・綜卦・錯卦）は鑑定書に載せない。

**間違い・トラブルへの備え**：メールの打ち間違い・忘れた・変えたい（**お客様が自分で解決、運営の手作業なし**：完了画面とログイン画面でお申し込み番号を使って直す・確かめる、マイページで変更）／二重申込（**お客様の自己責任・返金なし**。画面で注意喚起・二度押し防止済み。防止策として同じメールで有効な契約があれば2件目の申込を受け付けない）／決済失敗・中断（申込不成立・0円）／カード期限切れ（`past_due`→カード変更へ誘導）／マイページで解約できないとき（メールでも受付。特商法に明記済み。当社のシステム障害が原因なら連絡日を解約日として扱う）。

## 1. 課金モデル（方針A：カード必須＋自動更新）

- 無料期間は**お申し込み日を1日目とする7日間**。8日目に初回課金（9,800円・税込）、以後その日が毎月の更新日。開始にはカード登録が必要（無料期間中は請求なし）。お一人様1回限り。
- 無料期間・継続課金・カード変更・解約・決済結果の通知の具体的なやり方は、**テレコムクレジットの接続仕様書に従う**（同梱 `実装仕様_会員まわり_共通.md` §4）。
- 決済失敗時は `past_due`（アプリはログイン時・マイページで「カード情報を更新してください」）。
- 無料期間の最終日の前日に、終了のお知らせメール（続けない場合は最終日の23:59までに解約すれば0円）を必ず送る。

## 5. 無料の再取得防止＝ロック（★最重要・要サーバー実装）

**「無料お試しはお一人様1回限り。メールアドレスを変えても、二度と無料で使えないようにする」**

- 方針Aでは**カード登録が必須**なので、**カードが第一のロック**になる：
  同一カード（カードのハッシュ／識別子）で過去に無料体験済みなら、**無料を付与せず**「無料体験は利用済み」を表示し**有料開始のみ可**とする。
  これによりメールアドレスを変えても、同じカードでは再取得できない。
  ★決済代行注意：この判定には「**同一カードかを判定できる恒久ハッシュ/識別子**」が必要。決済代行のトークン決済でそれが取得可能かを**契約前に決済代行へ要確認**。取得できない場合は、下記の端末フィンガープリント＋（任意）SMS認証を主ロックにする。
- 補強として、メール以外の識別子も併用して同一人物/端末を検知：
  - 端末フィンガープリント（ブラウザ/OS/画面/フォント/Canvas 等のハッシュ）
  - Cookie＋localStorage の永続マーカー（単独では信頼しない）
  - IP／サブネット
  - （任意）SMS／電話番号認証を追加すればさらに強固
- 判定・保存・ロックは**必ずサーバー側**（localStorage 削除・シークレットモードで破られない設計に）。

## 6. API費用の抑制（★AIコスト対策・要サーバー実装）

Gemini の生成コストがかかるため、無料体験での使い過ぎを防ぐ：

- **カード必須**そのものが最大の抑止（冷やかし・大量アカウントを弾く）。
- **無料期間中の AI 生成は「1日3回まで」**（本鑑定＋深掘りチャットの合計。サーバー側で日次カウント。UTCではなく日本時間の暦日でリセット）。※フロントは `TRIAL_DAILY_LIMIT=3` で暫定実装済み。localStorage は改ざん可能な目安なので、本番は認証ユーザー単位でサーバー集計すること。
- **AI を使わない機能（立卦・顧客管理・PDF印刷）は無制限**（コストゼロなので体験価値は落とさない）。
- 有料プラン移行後の上限は別途設定（下記「有料プランのフェアユース」を参照）。
- **深掘り相談（鑑定結果画面の追加質問チャット）も、1問ごとに AI 生成を1回消費し、上記「1日3回」に合算する**（フロント実装も合算済み）。無料体験中も深掘りチャットは利用可能。別枠にしたい場合はサーバー側で調整。

### 有料プランの上限（「使い放題」＝通常利用は無制限。ただし赤字は絶対に出さないハード上限を置く）
有料プランは通常のご利用の範囲では**無制限＝使い放題（表記は維持）**。ただし bot・自動化・アカウント共有/使い回し・転売などの不正利用や万一の暴走でも**絶対に赤字にならない**よう、サーバー側にハード上限を置く（数値は非公開。「通常のご利用に回数制限なし」と案内）：
- **1日あたりのハード上限：100回**（`PAID_DAILY_CAP=100`。到達したら当日は停止。通常のプロ=1日20〜40鑑定では未到達）。
- **1か月あたりのハード上限：3,000回**（`PAID_MONTHLY_CAP=3000`。＝赤字防止の最終ライン）。
- **1分あたりのバースト上限：15回**（`PAID_RATE_PER_MIN=15`。スクリプト連打の防止）。
- **異常値の監視・アラート**：1ユーザーの日次/時間あたり回数、同一IP/端末からの多重アカウント、深夜の機械的アクセス等（ハード停止の手前で気づけるように）。
- 制限・停止の根拠は**利用規約 第8条（禁止事項・公正利用）**に置く。
- **赤字にならない根拠**（1鑑定≈¥0.57／月額¥9,800で計算。裏卦の深い解釈追加後の実測値）：
  - 月ハード上限3,000回に**張り付いても**AIコストは **約¥1,710/月**＝売上¥9,800の**約17%**（＝**粗利83%以上を常時確保**）。
  - 損益分岐は1人あたり**月約14,000鑑定（1日約470）**で、人間には到達不可能。
  - 現実的なプロ（月1,000鑑定）ならコストは**約¥570＝売上の約7%**。→ どの使い方でも赤字にならない。
- 実務上のコストの主対策は「無料期間の1日3回制限＋カード必須」。有料側の上記上限は**不正利用対策＋赤字の完全防止**の二重の意味を持つ。
- **深掘り相談の「命式連携」（四柱推命）**：任意入力の生年月日（＋時間）から年柱・月柱・日柱（時間ありなら時柱）をクライアント側で簡易計算し、プロンプトに「命式＝生まれ持った土台（易7割・命式3割で伴走）」として渡している。日柱はJDN基準で正確、年柱・月柱は立春/節入りを概略日（2/4等）で切替える簡易版のため**節入り前後1日はずれる可能性あり**。厳密にする場合は、四柱推命ソフト（pro）と同じ計算エンジンに差し替え可能。
  - **空亡（天中殺）**：日柱の干支が属する旬から余る2支を算出し、命式の情報行に「空亡：◯・◯」として**参考表示のみ**する（`calcPillars`の`p.kubo`）。断定を避けるため**AIプロンプトには渡していない**（＝鑑定文で「今年は空亡」等の年運の言い切りはしない方針）。年運まで踏み込む場合は姉妹ソフト（四柱推命PRO）の領分。
- サーバー側でレート制限＋アカウント単位の従量監視・異常検知。
- 当日の上限到達時は「本日の鑑定、おつかれさまでした（上限3回）／また明日、続きをお楽しみいただけます／料金プランを見る」を表示（フロント実装済み：`#trialLimit`）。

### 無料体験・最終日の有料案内（★要サーバー連携）
- **無料体験の最終日（7日目＝満了日当日）に、アプリ上部へ有料案内バナーを表示する**（フロント実装済み：`#trialFinalDay`。文言＝「本日が、無料体験の最終日です／明日からは月額プラン（9,800円）で、引き続きすべての機能を（いつでも解約OK）／料金・お支払いを確認する→upgrade.html」）。
- 最終日の判定に使う**無料開始日はサーバーDBが正**（決済代行の満了日管理と同じ日付を使う）。サーバーから「残日数」または「最終日フラグ」を渡し、フロントの表示を切り替えること。現在の実装は **localStorage `eki_trial_start`（初回起動日を起点）のデモ用の仮実装**なので、必ず差し替える。

## 11. 立卦・鑑定エンジンの構造（クライアント完結・サーバー移植は不要）

以下は**純粋なJS計算でコスト0・オフライン可**。サーバー化は不要で、そのまま使えます（AIに渡す「材料」を作る部分）。
- `TG`：八卦（三爻）データ。`HEXDB`：64卦の卦名・読み・卦辞・爻辞・テーマ・運勢・吉凶。`HEXKK`：吉凶ランク（A〜E）。
- `calcGoka(上,下)`：**互卦**（内に隠れた背景・本音）。`calcShika(上,下,変爻)`：**之卦**（この先向かう先）。`calcSoka(上,下)`：**綜卦**（相手の立場から見た卦。上下対称の8卦は本卦と同一）。`calcSakka(上,下)`：**錯卦**（陰陽をすべて反転＝正反対の可能性・裏側）。`calcPillars(生年月日,時)`：**命式＋空亡**（四柱推命の簡易計算）。
  - ※ 全64卦で「綜卦の綜卦＝本卦」を検算済み・0エラー。錯卦（乾⇔坤・泰⇔否・既済⇔未済 等）・空亡（戊午→子丑・甲戌→申酉 等）も検算済み。
- `buildResult()` がこれらを束ね、`buildPrompt()` が相談文＋卦の材料からAIプロンプトを構築（§12）。
- 立卦の入力は4方式：**易タロット（カード）・サイコロ・コイン・数字**。どれも同じ卦ロジックに合流。
- **命式連携（任意）**：深掘りで相談客の生年月日を入れると、四柱推命の命式（年柱・月柱・日柱／時柱）を簡易計算しプロンプトに添える（易7割・命式3割）。年柱・月柱は節入りを概略日で切替える簡易版のため**節入り前後1日ずれる可能性あり**。厳密化するなら姉妹ソフト（四柱推命PRO）の計算エンジンに差し替え可。

## 15. データ構造の実物（フロント localStorage → サーバーDBへ移す）

```jsonc
// localStorage['eki_pro_v1']
{
  "settings": {            // → provider_settings（占い師=user 単位）
    "brand":   "",         // 屋号（OEM表示名）
    "name":    "",         // 占い師名
    "role":    "",         // 肩書き
    "logo":    "",         // ロゴ（dataURL）
    "contact": "",         // 連絡先
    "accent":  "#c0392b"   // アクセントカラー（OEM）
  },
  "customers": [           // → customers（占い師が管理する相談客）
    {
      "id":   "…",
      "name": "…",
      "memo": "…",
      "history": [ /* 過去の鑑定（卦・相談文・生成結果など） */ ]
    }
  ]
}
```

- 他の localStorage キーは §10-4 の表を参照（`eki_pro_key`＝デモキー廃止／`eki_trial_*`＝サーバー集計へ／`eki_pro_lang`＝表示言語 ja|en|ko）。

## 19. 鑑定結果の表示仕様（フロント実装済み・移植時に維持）

AI が返す本文は `▼見出し：内容` 形式。`parseReading()` が各見出しを抽出して各枠へ表示する。**サーバー生成に変えても、この出力フォーマットと表示ルールは維持**すること。

- **見出し一覧**：`▼判定`（◎〇△✖＋一言）／`▼結論`（7点）／`▼一言`／`▼運気`／`▼裏卦`（互卦・綜卦・錯卦の解釈）／`▼台本`（読み上げ）／`▼状況`／`▼流れ`／`▼助言`（3点）／`▼注意`／`▼結び`。
- **裏卦（互卦・綜卦・錯卦）**：本卦の派生3卦を各2〜3文で解釈。表示は**卦ごとに色分け**（互卦＝紫／綜卦＝青／錯卦＝茶）。**之卦（しか）はこの枠に含めず**、専用の枠（`#shikaBox`）に表示。
- **重要ポイントの色分け**：プロンプトで核心語句を `【…】` で囲ませ、フロントで**黄色マーカー表示**（`fmtRich()`／`.hl`）に変換。適用は**台本・裏卦・判定のみ**（他項目は `fmtPlain()` で `【】` を除去＝ハイライトしない）。多用による読みづらさを避ける設計。
- **記号ルール**：**アスタリスク（＊）は一切出さない**（`callGemini` の戻り値で `／[＊*]/` を除去。プロンプトでも禁止）。「※・■・□・★・▶」等はOK。
- **読みやすさ（泣き別れ防止）**：本文コンテナに `text-wrap:pretty; word-break:auto-phrase;`（日本語の文節改行）を適用し、行末の1〜2文字孤立を防止（非対応ブラウザでは無害に degrade）。
- **言語：当面は日本語版のみ**（`app/index.html` の `LANG='ja'` に固定・言語切替ボタンなし・保存された言語設定も日本語に戻る）。英語・韓国語の訳データ（`I18N`・`HXT`）と出力言語の指示（`langLine`）は、将来海外向けに出すときのために残してある（今は使わない）。
- **命式・空亡**：命式（四柱推命）は「――命式から：」で本文と分けて添える。**空亡（天中殺）は命式情報行に参考表示のみ**でAIには渡さない（年運を断定しない方針。§6・§11）。

## 21. 用語集（易・四柱推命：エンジニア向け最低限）

- **本卦（ほんか）**：占ってまず立つ、今の状況を表す中心の卦（64種）。
- **変爻（へんこう）**：6本の爻のうち最も動く1本。今の注目点。
- **之卦（しか）**：変爻が動いた先に現れる卦＝この先の展開。専用枠 `#shikaBox` に表示。
- **互卦（ごか）**：本卦の内側に隠れた卦＝表に出ない背景・本音。裏卦欄に紫で表示。
- **綜卦（そうか）**：本卦を上下ひっくり返した卦＝相手の立場から見た状況。裏卦欄に青で表示。
- **錯卦（さっか）**：本卦の陰陽をすべて反転した卦＝正反対の可能性・裏側。裏卦欄に茶で表示。
- **卦辞／爻辞（かじ／こうじ）**：古典の言葉。難解な漢文を現代語に翻訳して鑑定文に反映。
- **立卦（りっか）**：卦を立てること。本ツールは カード／サイコロ／コイン／数字 の4方式。
- **命式（めいしき）**：四柱推命で生年月日から立てる年柱・月柱・日柱（＋時柱）。本ツールでは易の「土台」として伴走。
- **空亡（くうぼう／天中殺）**：日柱の干支が属する旬から余る2支。参考表示のみ（AIには渡さない）。

> 立卦・派生卦の計算は `app/index.html` 内の純JS（`TG`/`HEXDB`/`calcGoka`/`calcShika`/`calcSoka`/`calcSakka`/`calcPillars`）で完結。全64卦・派生卦を検算済み（§11）。
