# ニコカレ ロジック整理（相性ごよみ）

このサイトの目的は **「二人（または一人）の“相性の良い日／避けたい日”を、月ごとのカレンダーで突き合わせて見せる」** こと。
占い判定は四柱推命の確定計算をベースに、**乱数を一切使わず** `生年月日＋日付` から決定論的に導く。

---

## 1. 全体構成（3層）

```
┌──────────────────────────────────────────────────────────┐
│ index.html （画面アプリ／自己完結）                       │
│  ・二人の突き合わせ evalDay / monthScan / render          │
│  ・命式 PersonBazi（喜神・忌神）                          │
│  ・共有画像・QR・メモ・記念日・ICS/Googleカレンダー連携   │
│  ・engine.js と daily-engine.js を <script> でインライン埋込 │
└───────────────┬──────────────────────────────────────────┘
                │ 同じ計算・同じ文言を参照
┌───────────────┴───────────┐   ┌───────────────────────────┐
│ engine.js  (window.KEngine)│   │ daily-engine.js (window.KDaily) │
│ 四柱推命の“計算”だけ       │◀──│ 文言バンク＋日運生成         │
│ 日柱/干支関係/十神/十二運  │   │ generateDaily(...) を提供    │
│ 桃花/相性素点/シード       │   │ 計算は engine.js に委譲       │
└────────────────────────────┘   └───────────────────────────┘
        ▲                                   ▲
        └────────── 毎朝メール配信サーバ（Node）が同じ外部 .js を require ┘
```

**設計の核＝単一ソース**：画面（`index.html` のインライン版）と、メール配信サーバが読む外部 `engine.js` / `daily-engine.js` は
**同一内容でなければならない**。ズレると「画面には出るのにメールには出ない」といった食い違いが起きる。
（この同期は `tools/sync-engines.js` で検証・復元する。→ 第5章）

---

## 2. engine.js — 計算コア（`window.KEngine`）

DOM 非依存の純ロジック。テキストや描画は一切持たない。

| 機能 | 関数 | 内容 |
|---|---|---|
| 日柱 | `pillar(y,m,d)` | ユリウス通日から十干十二支を確定（アンカー 2000-01-01=戊午） |
| 干の関係 | `stemRel` | 干合／干相生／干比和／干相剋 |
| 支の関係 | `branchRel` | 同／支合／三合／沖／刑／害／破／支相生／支比和／支相剋 |
| 十神（通変星） | `juushin(D,T)` | 日干から見た相手干（比肩〜印綬） |
| 十二運 | `juniOf` | 長生〜養（陽干順行・陰干逆行） |
| 桃花 | `isTouka` | 相手の地支が自分の三合局の桃花か |
| 運命の相手 | `partner` | 干合かつ支合＝60分の1（天地徳合） |
| 素点/日運 | `compatRaw` `dailyIndex` | 独自指標（四柱推命に点数は無い＝当サービス指標） |
| シード | `daySeed` `personSeed` | 決定論的な文言選択の種 |

## 3. daily-engine.js — 文言＋日運生成（`window.KDaily`）

計算プリミティブは engine.js から取得し、ここでは重複させない。
役割は **文言バンク**（五行別アイテム、恋愛・仕事・金運・健康の一言、季節・節気、天気メッセージ 等）と、
その **決定論的な選び方** (`pickSeq` / `pickIdx`)。

### 中心関数 `generateDaily(birth, dateJST, opts)`
毎朝メール1通分の全スロットを返す“サーバ契約”。画面 `run()` と同一の式・同一バンク・同一シードで算出するため、
**画面とメールが絶対に食い違わない**（＝食い違ったら同期漏れ、第5章）。

主な出力スロット（現行版・34キー）:
`index / weather / grade / theme / en / love / loveMove / touka / special /`
`koyomi / element / bazi / lucky / place / fortunes / focus / season /`
`onepoint / morning / closeWord / **habit** / **moon** / **subject** / todayOne …`

> **habit / moon / subject** は新しめのスロット。過去にここが欠落した外部版が原因で
> メールの該当欄が空になる不具合があった（→ 第6章で修正済み）。

### グレード（相対評価）
天気・指数は本人の 60 干支スコア分布から相対的に決める：
`◎`=上位28%／`△`=下位15%／`💮`=桃花×高得点×非沖のレア／`〇`=それ以外。
さらに流年・流月（その年月の干支の喜忌）で `ymAdjust` が ±補正（効きは 0.6 倍に緩和）。

## 4. index.html — 二人の相性の突き合わせ

### 入力
- お一人目 `A` / お相手 `B`（生年月日・性別・出生時刻は任意）
- 目的 `pp`：`date`(デート) / `kokuhaku`(告白) / `shoubu`(勝負) / `nakanaori`(仲直り) / `friend`(友達)
- モード `mode`：`couple`（二人）／`solo`（一人）

### 突き合わせの心臓部 `evalDay(Y,M,D)`
1. その日の干支 `day = KE.pillar(Y,M,D)`
2. 各人と日柱の関係 `cA = rel(day, pA)`, `cB = rel(day, pB)`
   - 相性素点 `harmony = cA.sc + cB.sc`（干合+6/支合+8/三合+6…沖−8/刑−6…）
3. 各人の個人運グレード → `mood = (pa+pb)*2`（範囲 −4〜+8）
4. 目的別に合成式を切替：

   | 目的 | スコア式 |
   |---|---|
   | デート/友達 | `harmony + mood` |
   | 告白・プロポーズ | `harmony + romance`（不調は −4 ずつ減点） |
   | 勝負・大事な予定 | `harmony*0.5 + (pa+pb)*4`（個人運が主役） |
   | 仲直り・話し合い | `harmony + help + mood` |

5. マーク判定：
   - `×`（避けたい）＝ **沖のみ**（真っ向衝突。刑・害・破は厳しくしすぎない）
   - `△`（注意）＝仲直り時の刑・害、または score<0
   - `◎`（特に良い）＝ score≥11 ／ `○`（良い）＝ score≥4 ／ 無印＝ふつう

### 月表示
- `monthScan()` が当月全日で `evalDay` を実行
- `render()` がカレンダーを描画。二人モードでは今月の `◎` の上位3日を **⭐（二人の運命が動く日）** に昇格
- `renderSummary()` が「いい日一覧」「避けたい日一覧」を要約
- `detail(d)` が日別の理由（`whyText`）と各人の突き合わせカード（`pcard`）を表示

> 注意点として、**桃花（モテ運）は日支に対して刑/破になる星**なので、
> 「×は沖のみ」とすることでモテ日が×に落ちないようにしている（設計上の意図）。

## 5. 単一ソースの維持（tools/sync-engines.js）

`index.html` はエンジンをインライン埋め込み、外部 `.js` はメールサーバ専用、という**二重管理**のため、
片方だけ更新するとズレる。これを防ぐのが同期ツール。

```bash
node tools/sync-engines.js --check   # index.html と外部 .js の一致を検証（不一致なら exit 1）
node tools/sync-engines.js --write   # index.html を正として外部 .js を再生成
```

**運用ルール**：ロジック／文言は `index.html` を編集し、その後かならず `--write` で外部 `.js` を更新する
（または CI で `--check` を回す）。`engine.js` は計算のみ・`daily-engine.js` は文言のみ、という分担も維持する。

## 6. 過去の不具合と修正（記録）

- **症状**：外部 `daily-engine.js`（メール用）が `index.html` の最新エンジンに対して陳腐化。
  外部版 `generateDaily` は旧版（29キー）で、最新版が使う 16 個のバンク／ヘルパー
  （`MOON_MSG` `HABIT_ACT/HABIT_WHY` `WEARTPL_F/M` `TODAY_WHY` `LM_EFFECT/LM_SITU`
  `EN1_OBS/EN2_OBS` `WOBS` `KOU72/getKou` `JUNI_PHRASES` `ADV_SHARED` `pickRand`）が欠落。
  出力スロット `habit / moon / subject` が返らず、**毎朝メールの該当欄が空**になった。
- **影響範囲**：メール（個人日運）側のみ。**画面の二人相性マッチングは正常**（インライン版＝最新・完全版を参照するため）。
- **修正**：`index.html` の最新版を正として外部 `daily-engine.js` を再生成し、識別子・出力スロットを完全一致に回復。
  以後の再発防止として `tools/sync-engines.js` を追加。
